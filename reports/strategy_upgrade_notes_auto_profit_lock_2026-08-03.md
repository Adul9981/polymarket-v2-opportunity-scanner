# 策略优化升级说明：自动锁盈优先级提升

日期：2026-08-03

## 1. 这次新增的核心认知

当前项目已经完成第一版：手动输入比赛链接、选择策略 A/B、固定金额生成网格计划、成交后自动挂卖单。

这次复盘后，需要把一个能力提升为最高优先级：

```text
自动指引并快速锁定利润。
```

原因很直接：很多交易不是买点错，而是低位买对后，高位浮盈没有及时保护，最后在电竞尾盘高波动里把利润甚至本金全部还回去。

这类错误已经反复发生，不能继续依赖人工情绪判断。系统要承担这部分纪律。

我的实际操作大致是：

挂了 65c 卖单，卖出约 $90。

这场的核心问题不是低位买入，而是：

```text
已经有大额浮盈后，没有自动锁盈。
```

## 3. 心理问题需要产品化解决

人工交易时很容易出现以下心理：

```text
已经卖了一部分，所以觉得剩下可以拿到最后。
看到 80c 后，会自然想等 100c。
为了多赚最后一点，忽略了已经暴露的大额浮盈。
真正想卖时，往往已经错过最好的流动性和价格。
电竞尾盘价格变化太快，人工反应经常跟不上。
```

所以这里不能只做提醒。

更合理的是：

```text
系统在成交和浮盈出现后，自动生成并维护锁盈卖单。
价格达到关键区间后，自动卖出大部分。
只保留小额彩票仓。
```

## 4. 新增高优先级模块：策略 D2 自动锁盈

原来的策略 D 偏向“已有持仓救援 / 成本管理”。

现在需要拆出一个更明确的执行模块：

```text
D2：浮盈保护 / 自动锁盈
```

它不是新的买入策略，而是所有策略 A/B/C/P 都可以调用的执行保护模块。

适用场景：

```text
已经持有某方向仓位。
买入成本较低，当前价格已经明显上涨。
价格进入 60c-80c 区间。
用户心理上容易想拿到结算价 100c。
比赛还没有结束，尾盘仍有极高反转风险。
```

目标：

```text
先锁定本金。
再锁定主要利润。
最后只留下固定小彩票仓。
```

## 5. 第一版建议规则

### 5.1 对 20c-35c 买入仓位的默认锁盈

如果仓位平均成本在 20c-35c，默认执行：

```text
60c-65c：卖出一部分，至少回收本金。
70c-75c：卖出第二部分，锁定主要利润。
78c-82c：卖出第三部分，只保留小彩票仓。
```

建议默认保留：

```text
彩票仓成本：原始成本的 10%-20%
或固定 $5-$15
取两者中更小的值
```

### 5.2 对已经部分止盈后的剩余仓位

如果已经卖出过一部分，但剩余仓位仍然较大：

```text
不要把剩余仓默认视为彩票仓。
```

彩票仓必须满足：

```text
成本很小。
即使归零，也不会影响当场心态。
即使归零，也不会明显伤害日内收益。
```

如果剩余仓位市值或成本仍然较大，系统必须继续挂锁盈卖单。

### 5.3 高位回撤保护

如果价格曾经到达 75c-80c，但没有完全卖出，应启动回撤保护：

```text
触达 75c 后，如果回撤到 68c-70c，自动卖出主要剩余仓。
触达 80c 后，如果回撤到 72c-75c，自动卖出主要剩余仓。
```

这条规则是为了避免从 80c 一口气跌到 0c。

电竞市场中，这种变化可能只需要几分钟。

## 6. 和现有策略 A/B 的关系

策略 A/B 继续负责买入机会和初始卖出网格。

D2 负责成交后的浮盈保护。

逻辑关系：

```text
策略 A：20c-30c 分档买入，40c/50c/60c 分档卖出，保留彩票仓。
策略 B：强队临时回撤买入，反弹后分档卖出。
D2：当任何仓位浮盈扩大到 60c-80c 后，强制降低暴露，只保留小彩票。
```

也就是说：

```text
A/B 是入场策略。
D2 是出场纪律。
```

## 7. 需要配置会话优先完成的事项

### 任务 1：把 D2 加入策略模板

在策略配置中新增：

```text
D2_PROFIT_LOCK
```

建议字段：

```json
{
  "name": "D2：浮盈保护 / 自动锁盈",
  "type": "execution_protection",
  "applies_to": ["A_DEEP_REVERSAL", "B_FAVORITE_DIP", "C_EXTREME_LOTTERY", "P_PRE_POSITION"],
  "trigger_min_profit_price": 0.60,
  "major_lock_price": 0.75,
  "final_trim_price": 0.80,
  "max_lottery_cost_basis_usd": 10,
  "max_lottery_cost_ratio": 0.2,
  "trailing_protection": [
    { "after_touch": 0.75, "stop_price": 0.68 },
    { "after_touch": 0.80, "stop_price": 0.72 }
  ]
}
```

### 任务 2：交易计划里加入锁盈卖单

生成交易计划时，不只生成买入阶梯和普通卖出阶梯，还要生成：

```text
本金回收单
主要利润锁定单
彩票仓保留上限
高位回撤保护规则
```

尤其是低价买入后，如果价格涨到 65c 以上，不能只靠用户手动卖。

### 任务 3：状态摘要必须显示“还暴露多少钱”

状态摘要不能只显示盈亏，还要显示：

```text
剩余仓位成本
剩余仓位当前市值
已锁定利润
如果当前从这里归零，会损失多少未锁浮盈
当前是否已经超过彩票仓上限
是否应该继续卖出
```

这能直接提醒系统：现在不是“还能赚多少”，而是“已经有多少利润还没锁住”。

### 任务 4：监控器支持自动追加锁盈单

如果买单成交后，价格继续上涨，监控器应自动检查：

```text
是否已经挂了 65c/75c/80c 附近卖单
是否剩余仓位超过彩票仓上限
是否触发高位回撤保护
```

如果没有，就自动补挂或提示确认。

第一版可以先做半自动：

```text
系统生成明确动作。
用户确认后执行。
```

但最终目标应该是：

```text
对已经盈利的仓位，自动锁盈可以默认执行。
```

## 8. 第一版推荐优先级

最高优先级：

```text
成交后自动挂锁盈单。
```

第二优先级：

```text
剩余仓位超过彩票仓上限时，自动提示或自动减仓。
```

第三优先级：

```text
高位回撤保护。
```

第四优先级：

```text
机会发现层继续优化纠缠指数。
```

原因：

机会发现可以慢慢变好，但已经买对后的利润保护必须先解决。

## 9. 产品原则更新

新增一条产品原则：

```text
系统不是为了让我赚到最后一分钱，而是为了防止我把已经赚到的钱还回去。
```

对应执行原则：

```text
低位买入后，60c 以上开始回收。
75c 以上必须锁定大部分。
80c 以上只允许小彩票仓。
剩余仓位如果还能明显影响心态，就不是彩票仓。
```

## 10. 给配置策略会话的结论

请优先升级执行管理层，不要先继续扩展太多新入场策略。

本次最重要的升级是：

```text
把 D2 自动锁盈作为 V1.1 的核心能力接入 A/B 策略执行链路。
```

目标不是让策略更激进，而是让已经发生的正确交易能够被保存下来。
