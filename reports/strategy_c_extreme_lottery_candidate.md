# 策略 C 候选：极端低价反转彩票

> 状态（2026-08-09）：历史候选稿，已归并。本报告的"极端低价彩票"即
> docs/framework/STRATEGY_MASTER_LIST.md 的"中位反转-深反（S1-深反）"极值子类，
> 不属于独立策略，也不与 S3 理财局同名（S3 已于 2026-08-07 并入 S2 热门回撤接）。
> 执行口径：S1-深反彩票仓 + 彩票机器反弹确认层（单根拉升 >=10c），见 LOTTERY_MACHINE.md。

## 定义

策略 C 专门处理赛中价格跌到几美分的方向。

它不是策略 A 的普通低位网格，而是一个独立的彩票策略：

```text
价格极低
胜率很小
赔率极高
单次亏损可控
一旦反转，收益倍数很高
```

典型区间：

```text
3c-10c
```

## 为什么需要单独成策略

人在这种位置通常会有强烈抗拒：

```text
看起来快死了，不敢买
刚刚经历巨大下跌，不敢接
如果前面亏过，更容易被情绪影响
```

但电竞市场里，几美分并不总是归零。尤其是 LoL、Dota、CS 这类局内波动大的项目，团战、经济赏金、地图资源、残局失误都可能让价格从 5c 拉到 30c、60c，甚至 100c。

策略 C 的价值不是判断“它大概率会赢”，而是系统化捕捉：

```text
小概率 × 大赔率
```

## 和策略 A 的区别

策略 A：

```text
20-30c 买入
40/50/60c 分批卖出
仍然期待常规反弹
```

策略 C：

```text
3-10c 小额买入
买入时接受大概率归零
目标是 3x / 5x / 10x 或终局反转
绝不摊平成重仓
```

## 不能两边都买

策略 C 最大风险是两边都买。

禁止逻辑：

```text
不能因为 A 队跌到 6c 买 A
过一会儿 B 队跌到 8c 又买 B
```

原因：
这会把彩票策略变成双边亏损。极端波动时，两边都可能短暂给出低价，但最终只有一边结算为 100c。

第一版硬规则：

```text
同一小局，只允许一个方向进入策略 C
一旦 C 方向确认，另一方向禁止 C 买入
如果已持有赛前仓，C 仓必须单独记账
```

## 入场条件

第一版不要复杂化，先用价格和盘口行为：

```text
当前价格：3c-10c
最近 5-10 分钟有快速下跌
市场仍在更新，不是暂停/结算状态
盘口仍有成交，不是完全僵尸盘口
该方向没有被系统判定为明显终局归零
同一小局没有另一个方向的 C 仓
```

更稳的版本可以增加：

```text
刚从更高位置跌下来，不是一整局长期 1c-3c
低位后出现第一次向上跳动
或从 5c 反弹到 8c-10c 后回落
```

## 固定金额

策略 C 必须比 A/B 更小。

第一版建议：

```text
单次 C 仓：$3-$5
单场最多 C 仓：$5-$10
单场最多触发 1 次
```

禁止：

```text
亏了再补
从 8c 补到 5c，再补到 3c
因为前面赛前仓亏损而加大 C 仓
```

## 卖出计划

策略 C 不适合只等 100c。

第一版卖出：

```text
买入价 × 2：卖出 30-40% 成本份额
买入价 × 4：卖出 30-40% 成本份额
30c-40c：卖出一部分
60c+：卖出大部分
保留固定小彩票仓到结算
```

示例：

```text
6c 买 $5
12c 卖 $1.50 成本份额
24c 卖 $1.50 成本份额
40c 卖 $1.00 成本份额
剩余 $1.00 彩票仓
```

## 和现有样本的关系

已出现 C 候选特征的样本：

```text
NS-T1 Game 1：T1 最低 4.5c，最后 100c
DNF-BRO Game 2：BRO 最低 13.5c，接近 C 上沿
Dota2 GLYPH-PlayTime Game 2：PlayTime 最低 13.5c，接近 C 上沿
DK Game 1：DK 跌到 8c 后归零，是 C 的失败样本
```

这说明策略 C 一定要小金额，因为它会出现高倍盈利，也会出现直接归零。

## 当前状态

策略 C 目前是候选策略，不直接进入自动执行。

进入执行前需要继续验证：

```text
3c-10c 后的反弹概率
不同赛事/游戏的成功率
低位后第一次反弹是否有过滤价值
盘口成交量是否能过滤假机会
是否有必要只买原本强队或高人气队
```

## 第一版产品建议

先把策略 C 做成“提醒 + 手动确认”：

```text
系统发现 C 候选
提示：极端低价彩票，不是普通加仓
显示固定金额 $3-$5
显示最大可亏损
用户确认后生成 C 配置
执行层自动挂卖
```

等样本够多后，再考虑半自动执行。
