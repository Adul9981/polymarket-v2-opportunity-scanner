# BP 情报方法论（BP 即情报 · 假赛视角 · 闭环管理）

最后更新：2026-08-20

定位：**BP（选人/禁选）阶段是全场比赛信息密度最高的窗口**。BP 一落定，
观众常常就能判断"这场比赛大概率要输了"——这不是玄学，而是 BP 承载了
英雄熟练度、选手状态、教练意图与异常选择的复合信号。
本方法论把 BP 情报单独成层，与灰信号留痕（gray_entities）并列，闭环管理。

## 一、BP 阶段的价值维度（每个都要记录）

```text
1. 英雄熟练度：选手该英雄的历史胜率/战绩（如"cube 杰斯 2 胜不知道？"）——
   低熟练度硬选 = 强信号；
2. 选手质疑度：观众对该选手/该 pick 的质疑量级（"所有人都知道选杰斯必输"）；
3. BP 异常度：反直觉选角（对面无前排选巨魔、版本弱势英雄一抢）、
   位置/体系强行变换（如"换 Chovy 冰女点控"）、教练"抄作业"式 BP；
4. 教练责任：BP 决定权在教练，异常 BP 先怀疑教练（见第二节）；
5. 版本符号：负面选角预警（"二队杰斯=灾难""女枪等于 GG"）与强势体系
   （"永恩各大联赛没输过"）；
6. 图池/选图（CS 对应物）：CS 的 BP = 图池与选边（"MOUZ 自选图打不过"、
   "FUT 图三强图"），与 LoL 英雄 BP 同构。
7. BP 后战绩情报（2026-08-21 固化，关键）：pick 锁定后 1-2 分钟观众引用的
   "选手 × 英雄"历史战绩/胜率（"老李冰鸟7胜0负"）——熟练度锚点 + BP 决策
   评判 + 局内预期三重信息；区分正锚点（历史强=看好）与负锚点（历史弱=
   判负，如"cube 杰斯 2 胜"）；记录出现时间与多路共振；赛后回填应验与否。
8. 图池战绩情报（CS 对应物，2026-08-21 固化，同构）：图三转换窗口
   （上一局结束 → 下一张图确认）观众引用的"队伍 × 地图"历史战绩/强图
   （"FUT 米垃圾强图""这个图进攻零封过小蜜蜂"）——图池锚点 + 历史对位 +
   局内预期；记录时间与多路共振，赛后回填。标杆 Magic vs FUT 图三 Mirage
   （2026-08-19，23:39 两路共振，应验）。
```

## 二、教练与 BP 的假赛视角（倒推逻辑）

```text
1. 教练在 BP 上有很大决定权：选手不会玩的英雄、不熟悉的位置/体系，
   教练为"打假赛/做局"可能强制执行——这是观众质疑的常见靶点；
2. 倒推验证：比赛结果出来后回看 BP——
   "从 BP 就在演"（WE-EDG G1 杰斯）→ 结果输 → BP 判负应验；
   "内定首胜怎么选也没用"（WE-EDG G2）→ 结果输 → 应验；
3. 教练留痕：把"被 BP 质疑的教练"纳入 bp_entities（同 gray_entities 机制），
   再犯自动升级关注；
4. 纪律：BP 灰信号（教练/选手质疑）只作风险标注与复盘素材，不作假赛结论；
   但作为"价格失真候选"，与盘口/结果对照沉淀（可验证资产）。
```

## 三、闭环管理流程（BP 信号 → 验证 → 沉淀）

```text
1. S0/BP 落定 -> 立刻输出 BP 情报：
   双方选人/禁用、关键 pick、熟练度质疑、异常选择、观众共识/分歧、
   版本符号、BP 判负预测（"这 BP 大概率输"）、**BP 后战绩情报**（见第 7 条）；
2. 比赛结束 -> 回填验证：BP 判负/判胜是否应验（应验/未应验/部分）；
3. 沉淀三处（缺一不可）：
   - docs/data/intel/bp_signals.json：单场 BP 信号记录；
   - docs/data/intel/bp_entities.json：教练/选手 BP 留痕（再犯升级）；
   - matches.json games[].bp_intel：本场 BP 结构化字段；
4. 报告：局中（LIVE_INTEL_SCHEMA S0 节）+ 复盘（REVIEW_SCHEMA BP 节）
   必须包含 BP 情报，不能只列英雄名单；
5. 统计：BP 判负应验率、**战绩情报（正/负锚点）应验率**、教练质疑→异常
   结果率，反哺词表与阈值。
```

## 四、CS 与 LoL 分域

```text
CS 比赛与 LoL 比赛是两套体系，分开管理：
  LoL：英雄 BP（熟练度/位置/体系/教练）；
  CS：图池与选边（强图弱图/选图权/战术体系，如 K3 带猎鹰遗迹打法）。
两者的 BP 情报同构（都是"选完即判"），但词表、画像、盘口映射各自独立。
```
