# 情报输出时间轴框架（每场比赛 · 不同时间点输出什么）

最后更新：2026-08-23

用途：定义一场比赛从赛前到赛后，**每个时间点输出什么情报**。
目标：情报输出完整、清晰、周到——任何时间点打开都有一份"当前已知"的完整结构，未知项标"待观察 / 样本不足"，禁止删段。

## 一、时间点 × 输出内容矩阵

| 时间点 | 情报输出（每场） | 页面形态 | 更新机制 |
| --- | --- | --- | --- |
| 赛前（开赛前） | 预期情形：队伍画像、BP 预期、盘口结构、观众共识层（谁被看好 / 被质疑） | 赛前情报页 | 开赛前生成 |
| S0 选人 | 双方阵容 / ban-pick、counter、版本符号、BP 判负预测、熟练度质疑 | 局中快照 B（10 段骨架） | 60s 快照 |
| S1 0-10 对线 | 一血、对线优劣势、打野节奏、镀层 | B | 60s |
| S2 10-20 资源 | 先锋、前两条龙、经济差、换线 | B | 60s |
| S3 20-30 中期 | 团战节奏、第三条龙、单带、大龙决策 | B | 60s |
| S4 30+ 终局 | 龙魂、大龙、终结窗口、翻盘窗口 | B | 60s |
| 局间 | 本局小结 + 引用队伍 / 选手近期画像 | B 更新 | 局切换时 |
| 赛后（整场） | 整场复盘 A（10 段）：结果总览 / 逐局复盘 / 队伍画像 / 人员画像 / 灰信号汇总 / 联赛规律 / 预测验证 / 盘口 / 情报含义（LONG·SHORT）/ 数据溯源 | 复盘页 A + 闭环页 | 赛后自动 |
| 长期（跨场） | 队伍 / 选手 / 联赛画像 C + 统计（预测命中率 / 灰信号兑现率 / BP 应验率） | 画像页 C + 统计页 | 跨场累积 |

## 二、页面类型（INTEL_HTML_TEMPLATE，2026-08-21 定稿）

```text
类型 A：整场复盘页（10 段全集，赛后必出）
类型 B：局中深度情报页（A 的"进行中快照"，按 S0-S4 递进，结构永远完整）
类型 C：队伍 / 选手画像页（长期资产，跨场复用）
```

## 三、完整性铁律

```text
1. 结构永远完整：B 必须按 A 的 10 段骨架组织，未知 / 未发生段写"待观察 / 样本不足"，禁止删段。
2. 每段都带量：人员画像必须有提及量，禁止空表。
3. 引用近期画像：局中情报必须引用 teams / players / gray_entities 近期画像，不能只写本局。
4. 灰信号 / 预测 / 盘口：即使只有 1 条也要给结构，无则写"今日无信号"。
5. 每条情报可溯源：JSONL 路径 / 条数 / 数据窗口 / 待确认项。
```

## 四、闭环回填（发布佐证）

```text
局中记录（预测 + 灰信号 + 盘口）-> 赛后结果（多源交叉验证）-> 命中 / 落空 / 待确认
-> 统计（命中率 / 兑现率）-> 闭环页公开（如 WE vs LGD 样例）。
```

## 五、闭环页自动生成（流水线 v2，2026-08-23）

```text
结构化预测字段（matches.json 每场 predictions[]）：
  text（预测文本）/ time / category（result / bp / odds / gray）/
  status（pending / hit / miss）/ note（结果说明）。
局中记录：tools/record_prediction.py --match-id <id> --text "..." --status pending
赛后回填：同工具 --status hit / miss（或脚本更新）
闭环页生成：tools/build_closed_loop.py --match-id <id> --out <path>
  -> 有 predictions 直接读 JSON（v2，无歧义）；无则回退解析报告 HTML（v1，需人工复核）。
首个样例：WE vs LGD（4 命中 / 1 落空 = 80%），已回填 predictions[] 并验证 v2 生成。
```
