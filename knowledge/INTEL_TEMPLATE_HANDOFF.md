# 弹幕情报模板移交规格（供线上情报库工具参考实现）

> 版本：2026-08-26 · 用途：线上情报库工具按本文档生成与本站一致的弹幕情报页面。
> 建议阅读顺序：总纲 → 页面层级 → 模板规格 → 速览卡 → 多语言 → 硬性要求 →
> 门禁 → 示例页面（对照学习）→ 工具 → 参考文档 → 适配建议。

## 一、总纲（一段话）

弹幕情报页的使命：**用户进入页面 5 秒内，拿到"这场比赛什么情况、有什么关键信号、该关注什么"，辅助快速做交易决策**。
因此页面采用**决策导向结构**：核心情报速览（第一屏）→ 风险/锚点/盘口/共识（决策信号前置）→ 情报含义与决策落点 → 证据层（逐局/画像）→ 沉淀层（规律/验证/溯源）。
内容一律**结论先行、信号带量、可溯源**；弹幕只做过程佐证，结果标"弹幕口径·官方待回填"；灰信号只作风险标注，不作假赛结论；无样本不硬撑、无信号不硬造。
每份情报 **HTML + MD 双格式并存**，发布前必过**结果判定门禁**（四道闸）。

## 二、页面层级（整场 / 小局 / 局内节点）

完整情报按三层组织，命名与关系如下：

```text
系列（整场比赛）
├── 整场复盘页   <队伍A>-<队伍B>_full_<日期>.html(.md)
│    系列比分、逐局汇总、系列级灰信号/锚点/盘口、预测闭环、LONG/SHORT
├── 小局复盘页   <队伍A>-<队伍B>_G1_<日期> / _G2_ / …（每局一页）
│    该局 BP、结果、关键事件、该局灰信号/锚点、预测验证
└── 局内节点页   <队伍A>-<队伍B>_BP_|_S0_|_S1_|_S2_|_S3_|_S4_<日期>
      ├── S0 BP 节点（选人锁定）：BP 情报 + 锚点出现时刻 + 预期
      ├── S1 开局节点（0-10 分钟）：一血 / 对线 / 打野节奏
      ├── S2/S3 资源与中期节点：先锋 / 龙 / 团战 / 经济
      ├── S4 终局节点：龙魂 / 大龙 / 终结 / 翻盘窗口
      └── 特殊事件节点：灰信号爆发、盘口异动、关键转折
```

层级规则：
1. **节点页 / 局中页（B）= 整场页（A）的"进行中快照"**：B 沿用 A 的 12 段骨架，
   未发生段写"待观察/样本不足"，禁止删段；赛后 B 直接升级为 A；
2. **整场页顶部提供小局 + 节点导航**，层级之间可跳转；
3. 命名统一：联赛代码 + 队伍码（二队带后缀 .C/.Y），节点后缀
   `full / G1 / BP / S0 / S1 / live`，禁止混用。

## 三、12 段模板规格（A 型整场 / B 型局中通用）

```text
0  核心情报速览（第一屏 · 硬性门槛）
1  比赛信息与结果总览 / 状态核验（比分/进度/MVP + 官方待回填 + 跨源一致性提示）
2  灰信号汇总（风险红线 · 前置）
3  BP 锚点与选人情报（赛前强信号 · 前置）
4  盘口与市场讨论（机会信号 · 前置）
5  方向性情报板（锚点 × 共识 × 灰信号 · 一屏看方向）
6  情报含义与决策落点（LONG/SHORT + 本场观察点 · 前置）
7  逐局复盘（证据层）
8  队伍 / 人员画像（证据层）
9  联赛规律与版本（沉淀层）
10 预测验证回填明细（沉淀层 · 闭环）
11 数据与溯源（沉淀层）
```

设计逻辑：**决策层（0-6）回答"什么情况 / 有什么信号 / 该看什么"；证据层（7-8）回答"为什么"；沉淀层（9-11）回答"可信度 / 可复用"**。

## 四、核心情报速览卡（0 段 · 硬性门槛）

```text
1) 比分 / 进度一行（含"弹幕口径·官方待回填"标签）；
2) TOP 信号 3-5 条，按「风险 → 锚点 → 盘口 → 共识」顺序；
   每条 = 类型标签 + 一句话中文意译（≤30 字）+ 可溯源锚点（→ 详 §N）；
3) 一句话决策落点（"本场建议关注 / 边际信息在…"）；
4) 灰信号条目必须带"观众质疑·非结论"；无信号写"今日无信号"。
速览卡 = 无源不下结论；每条信号必须能跳转正文对应段。
```

密度要求（治"内容过多"）：弹幕原文样本每条信号 ≤2 条 + 计数；
长画像默认折叠（`<details>`），移动端优先显示信号层；人员画像保留 选手/提及/评价 三列；
逐局复盘必须保留 完整阵容（英雄+选手映射）、BP 后战绩情报、密度时间线锚点、转折点。

## 五、多语言弹幕呈现规范（韩 / 中 / 英）

```text
原则：主展示层全中文意译，原文只作溯源，"有翻译、不堆原文、保留黑话"。
1. 信号层只用中文意译一句话，不出现原文；
2. 原文引用折叠在 <details>，格式「中文意译（原文摘录）」，每条 ≤2 条；
3. 黑话保留双语：야필패=亚索必败、제필패=杰斯必败、마핸=让分盘；
4. 术语统一：官方英文 ID + 中文角色（如 Kangin（上）），队名映射登记 aliases；
5. 计数优先：韩/英文只聚合计数 + 翻译样本，翻不了标"待翻译"。
```

## 六、硬性要求（缺一不可）

```text
1. 结果/比分一律标"弹幕口径·官方待回填"；禁止把预测/玩梗当结果；
2. 灰信号：显著展示 + 条数/指向/预警 + 纪律声明 + 进统计页；
3. 方向性情报板：正锚/负锚/共识/灰信号四块齐列，无则写"今日无…"；
4. BP 后战绩情报必抓：pick 锁定后窗口的"选手×英雄"战绩提及，无则写"无战绩情报提及"；
5. 人员画像带提及量；BP/阵容给"为什么"（熟练度/体系/版本）；
6. 数据带量：总条数、提及量、密度峰值；
7. 每页至少 1 条可跨场复用的长期沉淀；
8. 无样本不硬撑，无信号不硬造；
9. HTML + MD 双格式并存（MD 为全文镜像）；
10. 收敛不丢硬信息：人员画像表 / 逐局完整阵容 / BP 战绩情报记录 /
    密度时间线锚点 / 跨源一致性提示 / 比赛元数据，六项禁止删除；
11. 数据完整性标注：实际数据源 / 预期数据源 / 缺口；
12. 时间口径：判定统一 UTC，页面按北京时间展示。
```

## 七、结果判定门禁（发布前强制）

```text
1. 时间门槛：开赛 <30 分钟禁止判定"已结束"；
2. 结构源优先：仅弹幕证据 → pending_official，禁止单凭弹幕情绪定胜负；
3. 反讽识别：英文弹幕 "ARE BACK / HOLY X / playing well.. mhm / WINS AGAIN /
   LO|LUL 结尾" → 不作胜者证据；
4. 比分源滞后：比分机器早于弹幕结束信号 >5 分钟 → 降级待确认；
   1-0/1-1 只是局末，系列终局须 2-0/2-1 或官方积分榜。
门禁不过 = 情报未交付。
```

## 十一、线上工具适配建议

```text
1. 线上库情报更完整：默认生成三层（整场/小局/节点），节点命名沿用 S0-S4；
2. 节点页 = 12 段骨架 + 节点专属事件（BP 节点突出锚点出现时刻，
   终局节点突出终结/翻盘窗口），节点之间保留时间线跳转；
3. 整场页顶部导航列出全部小局 + 节点页；
4. 数据更全时密度/提及量/灰信号计数可更高精度，但格式与阈值保持一致，
   避免两侧数据口径不一致。
```
