# 情报分层机制（长期记忆 / 短期记忆）

最后更新：2026-08-20

定位：情报自动落库不等于全部同权。按**价值时效**分层，像人脑的长期/短期记忆：
短期情报服务当下判断（赛后归档或淘汰），长期情报跨场累积（持续增值）。

## 一、三层分级

```text
LONG（长期记忆，跨场累积，持续增值）
  队伍/选手/教练画像（含灰信号与 BP 留痕）
  联赛规律与 BP 判负验证统计（如"杰斯必输""永恩连胜"）
  版本 meta 变化、图池强弱（CS）
  可验证资产：预测命中率、灰信号→兑现率、BP 应验率
  落库：teams / players / gray_entities / bp_entities / leagues /
        bp_signals（验证后）、matches（终态）

SHORT（短期记忆，本场/本局有效，赛后转化或淘汰）
  单局 BP 判断、盘中情绪/局势、当前预测、密度峰值事件
  落库：局中情报页、bp_signals（prediction 待验证）、matches.games 过程字段
  生命周期：比赛结束 -> 验证 -> 转 LONG（应验统计）或淘汰（噪音）

TRANSIENT（瞬时/噪音，不落库或仅计数）
  单条玩梗、广告、闲聊、表情刷屏
  用途：密度统计/事件锚点，不进入画像与结论
```

## 二、自动落库规则

```text
1. 每条情报入库时打 memory_tier 标签：long / short / transient（默认按上表）。
2. 自动流转：
   - 局中产出（BP 判断、局势、预测）默认 short；
   - 比赛结束复盘 -> short 项验证：应验的并入 bp_signals/gray_signals/
     prediction_validation（long 统计），未应验的标注后保留为样本；
   - 画像/留痕/规律只进 long，不进 short。
3. 报告与页面标注价值类型（如"短期：本局 BP 判断""长期：教练留痕"），
   用户一眼区分"现在能用"与"长期积累"。
4. 不做人工二次确认：自动落库，但 tier 判定规则固定、可审计。
```

## 三、与决策的关系

```text
- SHORT 情报：服务本场/本局判断（BP 判负、情绪、盘口讨论），时效性强；
- LONG 情报：服务跨场决策（队伍强弱、教练/选手留痕、规律统计），
  是"凡走过必有痕迹"与"BP 即情报"的底层；
- 下单前两者都要过：short 给当下方向，long 给置信度与再犯预警。
```

## 三.5 情报处理模型（2026-08-20 优化，输出结构固定）

```text
每局/每场结束后的情报输出，固定三段式，所有比赛一致（禁止时多时少）：

1.【本局复盘 · 短期记忆 SHORT】
   剧情 / 关键节点 / 弹幕共识与分歧 / 预测与验证（本局有效）
2.【决策可用情报 · SHORT→可验证】
   BP 判负、选手状态、盘口线索、下一局/下一场预测点（当局决策用）
3.【长期记忆沉淀 · LONG】
   选手/队伍画像更新、联赛规律、版本/BP 规律、灰信号留痕、
   可验证统计（预测命中率、灰信号兑现率、BP 应验率）（跨场复用）

局中情报与整场复盘是同一骨架的包含关系（INTEL_HTML_TEMPLATE 二.5）：
局中页必须带 LONG 内容（队伍/选手画像引用、规律、灰信号留痕），
不能只有 SHORT（本局情况）——这样局中情报本身就为整场复盘打了底，
赛后只是补全终态，不推倒重来。

流转规则：
  - 第 2 段的预测在赛后验证，结果回填第 3 段的统计；
  - 第 3 段是"凡走过必有痕迹"与"BP 即情报"的载体，跨场只增不改；
  - 用户看到的情报页必须三段落齐，缺一不可（可见性防错）。
```
