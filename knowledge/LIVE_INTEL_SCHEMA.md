# 局中实时情报标准（章节结构 + 阶段 Schema）

最后更新：2026-08-19

定位：与 `knowledge/REVIEW_SCHEMA.md`（赛后完整复盘）**配套**的盘中情报标准。
两者章节同源（队伍/选手/BP/局势/盘口/灰信号/预测/用户），差异在：
局中情报**按比赛阶段递进**输出，信息不完整是常态——**按结构输出"当前已知"**，
未知项标注"待观察/样本不足"，不硬凑。

```text
实时情报（进行中）  -> 按本文件章节 + 阶段递进，60s 快照，供盘中判断
完整复盘（结束后）  -> 按 REVIEW_SCHEMA 沉淀终态，引用实时情报与原始数据
```

## 一、比赛阶段划分（LoL 通用）

```text
S0 选人阶段（pick/ban）：阵容选择、BP 评价、counter、版本英雄/负面符号、
  英雄熟练度质疑、BP 异常度、教练责任（详见 knowledge/BP_INTEL.md）
S1 0-10 分钟（对线期）：一血、对线压制、打野节奏、镀层
S2 10-20 分钟（资源期）：先锋、前两条龙、经济差、换线
S3 20-30 分钟（中期）：团战节奏、第三条龙、单带、大龙决策
S4 30+（终局）：龙魂、大龙、终结窗口、翻盘窗口
```

## 二、局中情报章节结构（每份快照按此组织）

```text
0. 头部：比赛元信息 / 当前阶段（S0-S4）/ 阶段进度（如 18 分钟=中期）/ 数据窗口 / 健康状态
1. 当前阶段定位：一句话说明本快照处于哪个阶段、阶段主线是什么
2. 阵容与 BP 情报（S0 最重）：
   - 双方选人/禁用、关键 pick、counter 关系
   - 阵容评价（观众共识/分歧）与 BP 质量判断
   - 版本符号（如"二队杰斯=灾难"、"奥拉夫体系"）与负面选角预警
   - BP 判负/判胜预测：观众"这 BP 大概率输"信号（记录并赛后验证）
   - 熟练度质疑（选手该英雄历史战绩/胜率）与教练责任（异常 BP 先怀疑教练）
3. 阶段局势（按当前阶段递进）：
   - S1：一血归属/对线优劣势/打野路线/镀层
   - S2：先锋/龙/经济差/资源控制异常（如"优势不控龙"）
   - S3：团战节奏/第三条龙/单带/大龙决策
   - S4：龙魂/大龙/终结/翻盘窗口
4. 选手动态：本局表现 + **引用近期画像（players.json）**：
   - 近期状态（近 N 场）、焦点英雄与记录（如 Enosh 卡莎 11-0）、正负面标签
5. 队伍动态：领先/落后方、节奏异常、背靠背/管理问题等场外因素
6. 盘口/数字讨论：本窗口出现的数字盘与方向（总人头/让分/时长）
7. 灰信号/局内异常（含**预警等级**）：弱爆暗号/内讧/不控龙/选手分裂等四类信号；
   每条灰信号记录输出：
   - 预警等级：低（零星质疑）/ 中（集中质疑）/ 高（两路观众共振 + 时间集中 +
     盘口重合）
   - 市场含义（反手参考）：观众质疑集中在哪一侧 = 该侧价格可能失真（被做局/
     剧本叙事）；预警高 = 失真概率高，反手买入被低估侧是潜在机会，
     但必须配合盘口/价格验证与风控，灰信号本身不作假赛结论
8. 观众预测与分歧：本阶段的共识/少数派，跨阶段预测转向（如"2:0"->"打满"）
9. 事件与密度时间线：弹幕峰值时刻 = 关键事件锚点
10. 高价值用户（本窗口）
11. 数据与溯源：JSONL / status / 待确认项
```

## 三、隐性数据维度（局中必须主动引用）

```text
1. 选手近期表现：近 3-5 场状态/胜率/焦点英雄生涯记录（来源 players.json / 弹幕口径）
2. 队伍近期状态：连胜连败/换人/背靠背（如 DNS 换打野后连胜、背靠背体力隐患）
3. 历史交手：联赛/杯赛近期对阵（如 DNS 常规赛双杀 NS）
4. 联赛规律：LCK CL 少 2:0、LEC 打满率等（leagues.json）
5. 管理/场外：被放养/内讧传闻/薪资结构（会影响局内执行）
——这些在 BP 选出来那一刻就应触发检索，形成"选人即情报"。
```

## 四、与输出模板的对齐

```text
聚合页 intel_danmu_live_<session>.html 现有章节（队伍/选手/BP/局势/盘口/灰信号/
密度/高价值用户）保留；按本文件补齐：
  - 头部加"当前阶段 S0-S4 + 阶段进度"；
  - 选手章节引用 players.json 近期画像（"本局 + 近况"两行）；
  - BP 章节加阵容评价与版本符号；
  - 局势章节按阶段标签（S1/S2/S3/S4）组织事件；
  - 未知/未发生项写"待观察/样本不足"，不硬造。
```

## 五、灰信号预警 → 反手机会（交易情报价值）

```text
逻辑：观众集体质疑"假赛/剧本/卡盘"集中在某侧时，市场可能已被情绪/做局叙事
扭曲（如昨日 G2 BRO 91c->0.5c 三分钟崩盘，弹幕"瑞兹故意送"提前刷屏）。
输出：灰信号预警等级（低/中/高）+ 被质疑方向 + 对应盘口/价格观察点。
操作边界（红线）：预警只作"风险提示与价格失真候选"，不作假赛结论；
反手动作必须过盘口/价格验证 + 项目风控（S1-S4 框架内执行），不裸赌灰信号。
```
