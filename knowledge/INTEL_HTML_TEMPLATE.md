# 弹幕情报 HTML 标准模板（2026-08-21 定稿）

定位：从既有情报页中评选出的**标准模板**，所有弹幕情报输出必须参照执行。
评选依据：完整度（章节/数据量/溯源）+ 价值性（决策可用/长期沉淀/情报密度）。
与时间轴壳结合（2026-08-23）：比赛详情页 = 时间轴壳（局 -> 时间点切换），
每个节点 = 按本模板生成的完整页（A / B / C）；壳负责切换，模板负责内容。
节点映射与硬性门槛见 docs/task/MATCH_DETAIL_TEMPLATE.md 第 5 节。

## 〇、决策导向调整（2026-08-26 用户定稿，最高，覆盖下方章节顺序）

使命：**用户进入页面 5 秒内拿到"这场比赛什么情况、有什么关键信号、该关注什么"**，
辅助快速做交易决策。所有情报页（A/B/C 通用）按此执行：

```text
0. 核心情报速览卡（第一屏 · 硬性门槛）
   1) 比分/进度一行（含"弹幕口径·官方待回填"标签）；
   2) TOP 信号 3-5 条，按「风险 → 锚点 → 盘口 → 共识」顺序；
      每条 = 类型标签 + 一句话中文意译（≤30 字）+ 溯源锚点（→ 详 §N）；
   3) 一句话决策落点（"本场建议关注 / 边际信息在…"）；
   4) 灰信号条目必须带"观众质疑·非结论"；无信号写"今日无信号"。
   速览卡 = 无源不下结论；每条信号必须能跳转正文对应段。
1. 比赛信息与结果总览 / 状态核验（比分/进度 + 官方待回填 + 跨源一致性提示）
2. 灰信号汇总（风险红线 · 前置）
3. BP 锚点与选人情报（赛前强信号 · 前置）
4. 盘口与市场讨论（机会信号 · 前置）
5. 方向性情报板（正锚 × 负锚 × 群体共识 × 灰信号条件预测 · 一屏看方向）
6. 情报含义与决策落点（LONG/SHORT + 本场观察点 · 前置）
7. 逐局复盘（证据层）
8. 队伍 / 人员画像（证据层）
9. 联赛规律与版本（沉淀层）
10. 预测验证回填明细（沉淀层 · 闭环）
11. 数据与溯源（沉淀层）
```

设计逻辑：**决策层（0-6）回答"什么情况/有什么信号/该看什么"；证据层（7-8）回答"为什么"；
沉淀层（9-11）回答"可信度/可复用"**。内容结论先行、信号带量、可溯源。

密度与多语言：
- 弹幕原文样本每条信号 ≤2 条 + 计数；长画像默认折叠（`<details>`）；移动端优先信号层；
- 韩/英信号层只给中文意译一句话，原文折叠在 `<details>`（格式「中文意译（原文摘录）」）；
- 黑话保留双语（야필패=亚索必败、제필패=杰斯必败、마핸=让分盘）；
- 每份情报 HTML + MD 双格式并存（MD = 全文镜像，供情报库分析）。

### 多语言显示机制（2026-08-26 用户定稿，硬性）

```text
原则：默认中文可读，原文只作溯源、可展开查看。
  1. 速览卡 / 信号层 / 结论层 / 表格摘要：只显示中文意译，不出现裸露韩/英原文；
  2. 原文引用一律放 <details> 折叠，标签格式「中文意译（原文摘录）」；
  3. 黑话保留双语（야필패=亚索必败等）；翻译不了标「待翻译」，不硬翻；
  4. 计数优先：韩/英只聚合计数 + 翻译样本。
实现：快节点 prompt 已强制；速览卡提取若命中裸露韩文 -> 显示层折叠/标注。
```

> 下方"一、两种页面类型 / 二、类型 A 固定章节"等内容仍为内容与结构细则，
> 段落顺序以本节 0-11 为准（决策导向）；旧页不批量重排，新页按本节执行。

## 〇.1 节点粒度：S0-S4 三节点映射（2026-08-26 用户定稿）

每小局输出 3 个节点，阶段语义映射如下（不强制每局 5 个独立页）：

```text
BP 后（_bp） = S0 选人/BP：阵容、BP 评价、锚点出现时刻、预期
局中（_mid） = S1-S3 合并快照：对线/资源/中期主线，按当前进度标注阶段
局末（_end） = S4 终局：龙魂/大龙/终结/翻盘窗口
```

规则：3 节点为默认节奏（保持生成速度与成本）；关键局 / 决赛场次按需拆出
S1 / S2 / S3 独立节点（页面命名沿用 _g<N>_bp/_mid/_end，阶段写在页面标注里）。

## 〇.2 情报来源分层原则（2026-08-26 用户定稿，证据层总纲）

```text
1. 核心来源：每场比赛/每个节点，情报核心来自本场比赛的弹幕情报（真实弹幕依据）；
2. 补充来源（显式标注）：同场前几局弹幕与表现、队伍历史画像/能力、盘口佐证；
3. 合理推测：仅基于前局/已发生事件做适当推测，必须标「推测·待验证」，与事实分离；
4. 红线：无中生有绝对禁止；仅有简单推断、无数据支撑的不写；
   缺源显式标注（如 SOOP 离线=缺口），禁止用历史画像冒充本场数据；
   历史画像引用带时间；单源=待验证、多源共振=确认、方向背离=分歧。

呈现要求：每条结论带「证据来源」标签（本场弹幕 / 前局弹幕 / 历史画像 / 盘口 /
推测·待验证），溯源段逐条对应；推测不得与已发生事实混排。
```

## 二.5 A 与 B 是包含关系（2026-08-21 用户确认，重要）

```text
A（整场复盘）= 完整母版（10 段全集）；
B（局中深度情报）= A 的"进行中快照"，不是独立简化版。

规则：
1. B 必须按 A 的 10 段骨架组织页面，只是数据按"当前已知"填充：
   - 结果总览 -> 当前进度（S0-S4/第几局，未确认标注）
   - 逐局复盘 -> 当前局已发生片段 + 时间线（未发生写"待观察"）
   - 队伍画像 / 人员画像 -> 必须引用长期库（teams/players/gray_entities）近期画像，
     不能只写本局表现；
   - 灰信号汇总 / 规律 / 预测验证 / 盘口 -> 即使只有 1 条也要给结构，
     无则写"今日无信号/样本不足"；
   - 情报含义与后续 -> 必须给出"这一局信息对系列/后续的预测点"；
   - 数据与溯源 -> 必带。
2. 未知/未发生段写"待观察/样本不足"，禁止删段——结构永远完整。
3. 赛后 B 直接升级为 A：B 的骨架已就位，只需把"当前已知"补成终态，
   不推倒重来（这就是两者互通、包含关系的工程价值）。
```

## 二.8 方向性情报（锚点 × 群体共识 × 灰信号 · 2026-08-24 固化）

```text
定义：把"谁赢谁输"的线索按三个维度结构化输出——锚点（事实/战绩信号）、
群体共识（弹幕情绪信号）、灰信号（风险质疑信号）。三者独立、可交叉印证，
赛后统一回填验证，构成可验证的方向性情报。这是产品核心卖点之一。

### 结构（情报页必含板块，A 复盘 / B 局中 / C 画像均适用）

1. 正锚点（看好 → 谁赢）：对象 | 锚点内容 | 依据（战绩/版本/阵容/盘口）|
   出现时间 | 是否多路共振 | 赛后验证（应验/未应验/待定）
   例：Faker·冰鸟 7-0（BP 后战绩弹幕×2 路，21:19）→ 看好 T1 G3 → 应验
2. 负锚点（看衰 → 谁输）：对象 | 锚点内容 | 依据 | 时间 | 共振 | 验证
   例：cube 杰斯 2 胜（观众口径"选杰斯必输"）→ 看衰 WE G1 → 应验
3. 群体共识（弹幕情绪）：普遍看好 X（提及量/正情绪数）| 普遍看衰 Y |
   分歧点（如"3-0 vs 2-1"）——共识可量化，必须标注样本量
4. 灰信号风险（观众质疑，非结论）：对象 | 质疑内容 | 预警等级 |
   条件方向（若兑现 → 指向 X 输/赢）| 赛后兑现（兑现/未兑现/待定）
   纪律：只作风险标注与兑现统计，不作假赛结论

### 三者的关系（判断价值）
- 锚点方向 + 群体共识同向 = 强信号（多源共振）；
- 锚点方向 + 群体共识背离 = 分歧信号（更有价值，标注"分歧"）；
- 灰信号兑现统计 = 长期可验证的风险画像（gray-tracking），
  单场表述必须用条件式："若灰信号兑现，则指向……"，禁止结论式表述。

### 结构化落库（bp_signals.records 扩展）
每条锚点记录新增字段：
- anchor_type: "positive" | "negative"（正锚 / 负锚）
- direction: {"object": "Faker·冰鸟", "side": "favor" | "against"}
- consensus: {"count": N, "multi_stream": true/false,
  "sentiment": "pos" | "neg" | "mixed"}
- verdict: "应验" | "未应验" | "待定"（赛后回填）
```

## 二.10bis 关键情报价值呈现机制（BLUF × Key Judgment × So-What，2026-08-26 固化）

```text
背景：速览卡曾混入章节号/章节标题碎片（"3 BP 锚点与选人情报"、"10 预测验证回填明细"、
"灰信号留痕（入 gray_signals…）"），且只罗列事实/时间线，不写关键信息的价值。
用户定稿：**放不好就不放——速览卡只列关键信息，每条必须回答两问：
发生了什么（信号）+ 意味着什么（价值/含义）。**

参考业界做法（情报简报最佳实践，2026-08-26 检索）：
- BLUF（Bottom Line Up Front，结论先行）：第一屏先给结论；
- Key Judgment（关键判断）：每条判断一句话，证据与判断分离；
- So-What 检验：每条信息必须说明为什么重要（"5 秒知道意味着什么"）；
- 置信度校准：每个主要判断都带置信标签（多源确认 / 单源待验证 / 弹幕口径·待官方）；
- 3-5 条，按影响 × 置信 × 可行动性排序。

速览卡每条格式（硬性）：
  信号（发生了什么，含方向与关键对象）→ 价值/含义（意味着什么、为什么重要，
  ≤35 字，含方向与置信）＋溯源（→ 详 §N）。

禁止：
- 章节号/章节标题碎片（如"3 BP 锚点与选人情报"）；
- 元数据碎片（如"灰信号留痕（入 gray_signals / gray_entities）"）；
- 纯时间线（10:56→11:28→11:32）——除非附价值句；
- 表格头/维度词（位置/维度/验证状态/系列胜负）；
- 灰信号条目标签必须带"观众质疑·非结论"语义，禁止写成实锤。

实现与门禁：
- 生成端：fast_intel_node prompt 原生产出"信号+价值"条目；
- 兜底：tools/speedcard_consistency.py --fix 从正文重建 + LLM 改写缺价值条目；
- 门禁：vps_publish 发布前 --check 审计（empty / noisy / no_value 任一即阻止发布）；
- 回归：tests/test_speedcard_consistency.py（含 title/h2 拼接丢失信号句的教训）。
```

## 二.11 多语言弹幕呈现规范（2026-08-26 固化）

```text
背景：弹幕源含韩文（SOOP）、中文（虎牙）、英文（Twitch/Kick），
目标用户以中文阅读为主。原则：主展示层全部中文意译，原文只作溯源，
"有翻译、不堆原文、保留黑话"。

1. 信号层（速览卡/灰信号/锚点/盘口/共识）：只用中文意译一句话，
   不出现原文；需要精确性时附「（原文）→（中文）」但 ≤2 条/信号。
2. 原文引用格式（证据层）：韩/英文原文用小字+折叠（<details>），
   格式统一为「中文意译（原文摘录）」；禁止整段罗列未翻译弹幕。
3. 黑话保留：社区符号词保留原文+解释（야필패=亚索必败、제필패=杰斯必败、
   마핸=让分盘）——黑话是跨场可沉淀的信号符号，必须双向标注。
4. 术语统一：队名/选手名用官方英文 ID + 中文角色（如 Kangin（上）），
   队名映射登记 leagues/aliases（키움=KRX.C、폭스=BFX.Y）；禁止同页混用多种写法。
5. 计数优先：韩文/英文弹幕只聚合计数 + 翻译样本，不做逐条直译；
   无翻译能力的词条标注「待翻译」，不硬译。
```

## 四、硬性质量门槛（不达标视为未完成）

```text
1. 数据必须带量：弹幕总条数、提及量、密度峰值——禁止无数据空谈；

5. 每页至少 1 条可跨场复用的长期沉淀（画像/规律/留痕）；

8. **方向性情报必出**：正锚/负锚/群体共识/灰信号条件预测四块齐列；
   无锚点写"今日无锚点"，无共识写"共识不足"，无灰信号写"今日无灰信号"
   （2026-08-24 固化，用户确认为产品核心卖点）。
9. **核心情报速览必出**（0 段，第一屏）：比分 + TOP 信号 + 决策落点，
   每条可溯源（2026-08-26 固化）。
10. **多语言呈现达标**：信号层全中文意译，原文折叠且 ≤2 条/信号，
    黑话双语标注，队名/选手名统一（2026-08-26 固化）。
11. **收敛不丢硬信息（2026-08-26 固化）**：任何"精简/收敛/重排"改版，
    必须做完整性回归，以下硬信息项缺一不可，禁止为版面清爽删掉：
    人员画像表（带提及量）/ 逐局完整阵容（英雄+选手映射）/

12. **证据引用要求（2026-08-26 固化，最高）**：所有 BP/阵容/选手归属/
    局势结论必须基于真实弹幕数据并**带时间戳+来源**（如"19:04 硕硕"）；
    无法从弹幕确认的信息一律标"待确认/待官方阵容"，禁止用观众建议、

13. **来源分层标签（2026-08-26 固化，最高）**：情报页每条"信号级"结论

13b. **外推与闭环（2026-08-26 用户确认）**：
     · 外推三型（简单/条件式/因果）均允许，但必须明确外推条件：
```
