# 弹幕意见聚类与归因机制（Opinion Clustering & Attribution）

> 2026-08-26 用户提出，情报加工层设计。定位：把"表述不同但意见相同"的弹幕
> 合并成意见簇，做归因分析，输出结论性内容——比"提及数+正负"更深一层，
> 是共识层/群体智慧的核心加工。

## 一、为什么需要

现有情报输出"队伍/选手提及 + 正负计数 + 样本"，但：
1. 同一意见表述多样（"어차피 키움승임" / "이건 피어엑스 승이야 반대" / "FearX 这阵容
   就是等输"）——直接列原文会显得零散，看不出"普遍不看好某队"；
2. 缺归因：观众为什么这样看（哪个选手/哪波团/哪个 BP）没被结构化；
3. 缺结论：没有形成"关键结论性内容"供快速决策。

## 二、处理流程（四步）

```text
1. 意见抽取（Opinion Extraction）
   从窗口弹幕抽"意见句"：对象（队伍/选手/BP/盘口/局势）+ 立场（看好/看衰/质疑/中性）
   + 理由片段 + 时间点；无对象/无立场的纯情绪不计入。

2. 意见聚类（Clustering）
   把相同"对象+立场"、不同表述的样本合并为一个意见簇：
   - 簇 = {对象, 立场, 条数, 时间跨度, 代表样本(≤3, 去重后), 原文折叠}
   - 同簇内样本必须归一同一对象（team_names 归一）；
   - 簇的条数 = 该对象+立场命中数（不是去重后的样本数）。

3. 归因分析（Attribution）
   对每个主要簇，从样本中提取高频原因（选手/英雄/时间点/事件）：
   - 如"不看好 FearX"簇 -> 原因：Grizzly 梦魇送头（11:21/11:28）、全近战阵容、
     BP 四局连败评；给每个原因带出现次数/时间锚点。

4. 结论输出（Conclusion）
   生成"群体意见与归因"结论块：
   - 主流意见（簇名 + 条数 + 时间 + 主因）
   - 分歧点（对立意见簇或少数派，标样本量）
   - 一句话情报含义（对市场判断的含义，如"共识偏 FearX 输 -> 与盘口方向同向"）
```

## 三、输出结构（进 intel JSON + 页面区块）

```json
{
  "opinion_clusters": [
    {
      "object": "bfx.y",
      "stance": "看衰",
      "count": 27,
      "window_utc": ["2026-08-25 11:18", "2026-08-25 11:30"],
      "reasons": [
        {"cause": "Grizzly 梦魇送头", "hits": 11, "anchors": ["11:21", "11:28-29"]},
        {"cause": "全近战阵容被质疑", "hits": 6, "anchors": ["BP"]},
        {"cause": "BP 四局连败评", "hits": 5, "anchors": ["11:15"]}
      ],
      "samples": ["어차피 키움승임 못이긴다 조합이", "이건 피어엑스 승이야(反讽)", "피어 한타가질수가없다니까"],
      "divergent": {"object": "bfx.y", "stance": "看好(团战)", "count": 3, "anchors": ["11:24"]}
    }
  ],
  "opinion_conclusion": "观众普遍看衰 FearX（27 条，11:18-11:30），主因 Grizzly 梦魇送头 + 全近战阵容；少数派认可其团战阵容（11:24 分歧）——共识方向与盘口/G4 结算一致。"
}
```

页面：情报页新增"群体意见与归因"区块（决策层，放在方向板附近）：
主流意见 / 归因（原因带锚点）/ 分歧点 / 一句话结论。

## 四、实现方案

1. 规则层先产出候选：danmu_intel 已有队伍/选手提及+样本，按窗口把样本喂给
   聚类步骤；
2. 聚类用 LLM（DeepSeek，快节点同通道）：输入 = 规则层统计 + 代表样本，
   输出 = 上面 JSON 结构（带条数与时间锚点，禁止编造——只归纳给定样本）；
3. 快节点生成时把"群体意见与归因"作为独立区块写入页面（决策导向，放方向板后）；
4. 结构入库：intel JSON 增加 opinion_clusters 字段；跨场归因累计到
   teams/players 画像（如"FearX 打野送头"重复出现 -> 队伍级观察项）。

## 五、纪律

- 聚类只归纳给定样本，禁止编造弹幕/计数；条数必须可溯源到窗口；
- 反讽/玩梗先做语气判定（沿用结果门禁的反讽识别），不把反讽当正向意见；
- 主流意见 ≠ 结论；结论必须有方向/时间/样本量，且标注"弹幕口径"。
