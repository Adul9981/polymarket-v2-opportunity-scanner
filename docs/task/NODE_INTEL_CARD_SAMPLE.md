# 节点情报卡样例（第一版 · WE vs LGD G2）

> 用途：演示"节点情报卡"的固定 schema 与证据引用，作为 Agent 提炼的输出标准。
> 数据来源：2026-08-22 WE vs LGD（LPL BO3）整场弹幕情报 + 结构化库。

## 卡片

```text
比赛：WE vs LGD（LPL · BO3 · 2026-08-22）
节点：G2 · 前 10 分钟（对线期 S1）
时间：16:05-16:15（北京时间）

队伍情报
  - LGD 下路（卢锡安 / 女警）对线被压
    证据：弹幕负面提及"少爷卢锡安"（脱敏）｜状态：待验证

选手情报
  - WE 打野 Monki 再次被集中质疑（连续第三场）
    证据：弹幕多次点名 + 跨场记录 08-19 / 08-21 / 08-22｜状态：已验证（本场兑现 2/3）

BP 情报
  - 版本符号：杰斯 / 卢锡安 = 负锚点候选
    证据：观众"卢锡安负锚点"共识 + 赛后战绩对照｜状态：待验证

盘口讨论
  - "资本告诉你1:1"（16:08）
    证据：弹幕原文（脱敏）｜状态：已验证 · 命中（LGD 扳平 G2）

灰信号
  - 做局质疑 3-5 条，指向 WE 侧（"这演技拙劣"等）
    等级：中｜证据：弹幕聚合计数｜状态：待验证（观众质疑，非结论）

密度峰值
  - 官方流 104 条/分（16:11 附近，关键团战/翻盘窗口）

高价值用户观点
  - 本节点未识别到高价值用户观点（无 → 如实标注）

状态汇总：已验证 2 / 待验证 4 / 存疑 0
```

## 生成规则（Agent 提炼时遵守）

```text
1. 每节点一张卡，结构固定（比赛 / 节点 / 时间 / 队伍 / 选手 / BP / 盘口 /
   灰信号 / 密度 / 高价值用户 / 状态汇总）。
2. 每条情报必须带证据（脱敏弹幕原文或时间点或跨场记录）。
3. 状态分级：已验证（结果回填后）/ 待验证 / 存疑——"待验证"是诚实机制，不是缺陷。
4. 无内容就写"无"，不硬凑（无样本不硬撑）。
5. 灰信号只聚合 + 标注"观众质疑，非结论"。
```
