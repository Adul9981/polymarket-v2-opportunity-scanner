## 一、比赛状态与时间（最易错，2026-08-25 已大排查）

```text
E1 未开始比赛被误判"已结束"
   教训：GX-G2、CS2 10 场在开赛前被弹幕闲聊词误判，生成假复盘页。
   防线：结束检测必须"已开始且进行 ≥30 分钟"（AGENTS.md 12d，已实现）。
   待补：回归测试锁定该门槛。
E2 已结束比赛显示"进行中"
   教训：BLG-AL（08-23）、BoomBoys（08-22）曾显示进行中。
   防线：状态判断真实时间优先（start/end + closed + 完整情报页权威信号）。
   待补：回归测试锁定。
E3 已开始比赛显示"未开始"
   教训：GX-G2 北京时间凌晨开赛后旧页仍标未开始。
   防线：页面每日刷新 + 真实时间判断；待补：每日自动刷新流水线。
E4 跨时区日期误判
   教训：UTC 日期与北京时间比较导致 GX-G2 误判结束。
   防线：禁止 UTC 日期直接比北京时间（AGENTS.md 12d）；统一用 ISO+时区解析。
E5 开赛时间字段用错
   防线：以 market 层 gameStartTime 为准，event startDate 是挂牌时间
    （AGENTS.md 防错 2，已有）。
E6 时间显示格式错误（"08-24 08-25 00:00"）
   防线：fmt_time 统一北京时间输出（已修）。
```

## 五、站点 / API / 权限

```text
E20 线上验证走错地址（自定义域名 301 未跟随）
   防线：验证走用户真实路径（AGENTS.md 12c，已有）。
E21 发布流程覆盖站点注入内容（reports 覆盖导航/打点）
   防线：publish 内注入 nav/打点（已修）。
E22 跨域 API 缺 OPTIONS 预检（浏览器失败、curl 成功）
   防线：verify/lead/track 处理 OPTIONS + 模拟浏览器预检测试（已修，api/README）。
E23 会员名单不同步/过期
   防线：名单存服务器 + expires 校验（已有）；待补：到期提醒（TG 通知管理员）。
E24 统计被刷 / 打点缺失
   防线：统计仅作参考；待补：速率限制（简单 IP 限频）。

E25 导航样式不统一（下划线/字号/加粗忽变）
   教训：2026-08-25 导航链接未完整内联（缺 text-decoration:none/固定字重），
   被各页面 CSS 影响；根页/子页链接路径也一度不一致。
   防线：统一导航链接完整内联样式（text-decoration:none + font-size 固定 +
   font-weight 固定），回归测试锁定（test_site_framework）。
E26 服务器自动发布与本地站点 push 冲突
   教训：2026-08-25 live 监控页被服务器每次刷新推送 + 本地 nav 注入同时修改，
   持续 merge 冲突，导致 GX-G2 等情报一度推不上去。
   防线：vps_publish 以远端为基线（fetch + reset --hard origin/main）后
   复制/注入/提交/推送，站点仓库只作发布通道；本地发布前 pull。

E27 今日情报页"网站架构与显示"（头号防错对象，2026-08-25 用户定调）
   教训：今日页/详情页导航反复出错（旧模板导航覆盖注入结果、壳+iframe 双导航、
   嵌入脚本重复、实时页缺付费墙、双端推送冲突），原因都是"多套导航源 +
   发布无审计 + 测试不全"。
   防线（固化）：
     a. 导航单一来源：所有生成器（update_site_today / build_timeline_shell /
        intel-report 等）不再自带导航，统一由 add_site_nav 注入；
     b. 发布顺序：先重建今日页 -> 注入 nav/favicon/paywall -> 站点结构审计
        （每页 1 导航 / 今日页无旧模板残留 / 实时页必须带付费墙 / embed≤1），
        审计失败阻止发布（vps_publish.audit_site）；
     c. 详情壳嵌入模式（?embed=1）隐藏内页导航，避免双层导航；
     d. 回归测试：tests/test_today_page.py（今日页导航/明日预告/无旧比赛/
        首页公告位置/详情壳嵌入）+ test_site_framework.py（每页 1 导航/
        注入幂等/付费墙边界）；
     e. 服务器自检：vps_self_check 每 5 分钟对 site_repo 做站点结构审计，
        异常写入 self_check_report.json 并告警。
```
