# 比赛详情统一模板 + 网站主页 + 交互链路（2026-08-23 定稿）

## 1. 统一模板（两级选择器壳）

任何比赛套用同一个壳，结构固定：

```text
第一级：局（G1 / G2 / G3 ... / 系列复盘）
第二级：时间点（赛前 / BP / 局中 / 复盘）——随所选局自动切换
内容区：该时间点对应的完整情报页（iframe 内嵌，信息零丢失）
缺失节点：显示"暂无 · 待产出"，绝不 404
顶部：只读时间线概览条（每局关键事件一句话）
```

节点页约定：

```text
局中 = 中韩合并页（node_<id>_g<N>.html：中文完整页 + 韩文 SOOP 完整页叠放）
复盘 = 整场复盘页（10 段）
系列复盘 = 10 段完整页（match_<id>_series.html）
画像 / 统计 = 跨场页（intel_profile_* / intel_gray_*）
```

生成方式：`tools/build_match_page.py --match-id <id>`（自动探测节点页是否存在，
存在则挂载，不存在标"暂无"）；DNS vs NS 为标杆实现（match_kcup_dns_ns_2026-08-18.html）。

## 3. 全站交互链路

```text
主页（今日比赛 + 筛选）
  -> 点进一场比赛 -> 比赛详情（两级选择器：局 -> 时间点）
      -> 赛前 / BP / 局中（中韩合并完整页）/ 复盘（10 段）
      -> 系列复盘（10 段完整页）
      -> 跨场跳转：队伍画像 / 选手画像 / 灰信号统计 / 历史对局 / 市场链接
比赛结束后：节点情报自动产出 -> 详情页自动长出新节点 -> 系列复盘页自动生成
```

## 5. 节点页生成标准（结合 INTEL_HTML_TEMPLATE，2026-08-23 定稿）

时间轴壳负责"切换"，节点页负责"内容"——每个节点 = 按
knowledge/INTEL_HTML_TEMPLATE.md（A/B/C 三类 + 10 段）生成的完整页。

```text
时间点      -> 模板类型     -> 核心内容（必含）
赛前        -> A 骨架(未开赛) -> 头部 / 预期情形 / 队伍画像 / 盘口结构 / 灰信号先验
BP         -> B 型(BP 锁定)  -> 阵容 BP 深度拆解 + BP 后战绩情报（必抓）+
                                熟练度锚点（正/负）+ BP 判负预测
局中        -> B 型(S0-S4 递进) -> 10 段骨架按"当前已知"填充 + 密度峰值 +
                                灰信号 + 可验证悬念（赛后回填）
复盘（局末）-> B -> A 升级    -> 终态 10 段（不推倒重来）
系列复盘    -> A 型全集       -> 10 段 + LONG/SHORT 分层
画像        -> C 型           -> 跨场复用（teams/players/gray_entities）
```

硬性门槛（不达标视为未完成）：

```text
1. 结构永远完整：B 按 A 的 10 段骨架，未知段写"待观察 / 样本不足"，禁止删段。
2. 数据必带量：弹幕条数 / 提及量 / 密度峰值。
3. 灰信号显著展示 + 纪律声明 + 进统计页。
4. 结果 / 进度标"弹幕口径 · 官方待回填"。
5. BP 后战绩情报必抓：pick 锁定后窗口抓"选手 × 英雄 战绩/胜率"提及，
   无则写"无战绩情报提及"（正锚点 / 负锚点 / 教练决策质疑）。
6. 每页至少 1 条跨场可复用长期沉淀（画像 / 规律 / 留痕）。
```
