# 假赛案例公告标准模板（Case Standard · 2026-08-25 固化）

> 定位：把"赔率异常 + 比赛行为异常 + 弹幕灰信号"的可观察组合记录为**疑似**案例，
> 统一成 MD 案例库条目 + HTML 公告页两件套。样例：GIANTX vs G2（2026-08-24，案例 5）。
> 纪律：灰信号是观众质疑、非假赛结论；任何"确凿"结论必须由外部证据支持，
> 否则一律标"高度疑似 · 待核查"。数据必须可溯源（弹幕原文+时间点 / 盘口价格路径 / 来源）。

## 一、案例库 MD 条目模板（knowledge/leagues/FIXED_MATCH_SUSPECT_CASES.md）

```text
## 案例 N：<队伍A> vs <队伍B>（<日期>，<联赛>）
状态：<疑似 / 高度疑似（+ 判断依据）>；无外部证据注明"待核查"
背景：<排名/账面/赛前大热程度/特殊叙事（如名人堂、连胜）>
结果：<比分，官方口径 + Polymarket 结算确认>
局内路径：G1… / G2… / G3…（谁赢、怎么赢、异常点）
价格路径（Polymarket 系列盘 · UTC）：赛前 -> 逐局 -> 终局（关键转折点时间+价格）
  关联盘：让分 / 总局数等结算
灰信号（弹幕口径，观众质疑非结论）：条数 + 来源路数 + 方向 + 原文样例 + 兑现状态
选手实力 / 临场差异（弹幕口径）：核心正锚/负锚、被集火对象、盘面预期
命中"假赛疑似通用信号"：第几条
定性：事实层（可证实）vs 定性层（需外部证据）
交易可操作结论：高位锁盈/减仓、不反向追单
核查清单：官方调查 / 选手回应 / 复盘录像 / 盘口资金 / 后续表现
```

## 二、HTML 公告页模板（tools/templates/case_page_template.html）

固定五段结构（页面编号即章节号）：

```text
1 情报库提示      -> 本场情报页 / 灰信号统计与兑现率 / 案例库入口 + 数据完整性说明
2 赔率变化        -> 价格路径表（时间 | 价格 | 节点）+ 关联盘结算 + 观察结论
3 灰信号汇总      -> 命中数 + 来源 + 统计口径缺口 + 四维表（方向/预警等级/市场含义/兑现状态）
4 双方临场与实力  -> 两队账面/临场/关键信息对照表 + 异常组合说明
5 纪律声明        -> 观众质疑非结论 + 高度疑似待核查 + 交易提醒
```

样式：SAP/Apple（浅底 #f5f5f7、白卡片、单一强调色、系统字体栈）；顶部"案例公告"橙色标签；
文件名 `intel/case_<slug>.html`；上线后首页"案例公告"卡同步更新。

## 三、首页置顶公告卡统一格式（2026-08-26 用户定稿，新增案例必须遵守）

首页"案例公告"置顶卡内，**每个案例一行、布局完全一致**（教训：G2 与 KRX.C 曾
一个按钮在右、一个按钮在下，视觉混乱）：

```text
┌ 案例公告 ｜ 假赛疑似案例 · 观众质疑，非结论 · 待官方核查
│ ① 标题（加粗，如：GIANTX vs G2（LEC）：经典"大热崩盘"假赛疑似案例）  ｜ 查看案例 →
│    一句话摘要（灰字，如：灰信号 31 条共振 · 盘口 94.5c → 0.05c）        ｜ (右对齐按钮)
│ ─ ─ ─ ─ ─（虚线分隔）
│ ② 标题（加粗）                                              ｜ 查看案例 →
│    一句话摘要（灰字）                                        ｜
└
```

规则：
1. 每个案例 = 一行横向卡片：左侧（序号 + 加粗标题 + 灰字摘要），右侧"查看案例 →"
   按钮**同行右对齐**（`display:flex;justify-content:space-between;align-items:center`）；
2. 案例之间用 `border-top:1px dashed #ffe3b3` 分隔；序号 ①②③…递增；
3. 顶部固定：橙色"案例公告"标签 + 一句纪律说明（观众质疑，非结论 · 待官方核查）；
4. 新增案例步骤：① 写案例库 MD 条目（第一节模板）→ ② 生成 `intel/case_<slug>.html`
   五段式公告页 → ③ 首页按本格式追加一行（并提交推送，避免发布变基覆盖）。

## 三、生成与上线流程

```text
1. 先整理 MD 条目（按第一节模板）追加到 FIXED_MATCH_SUSPECT_CASES.md；
2. 复制 tools/templates/case_page_template.html，按 {{占位符}} 填充，
   另存 intel/case_<slug>.html（灰信号/价格路径必须给原文+时间点，可溯源）；
3. 首页公告卡：新增/替换顶部的"案例公告"卡片，链接到新案例页；
4. 运行 tools/add_site_nav.py 统一导航，推送 GitHub Pages；
5. 回归测试 tests/test_site_framework.py::test_case_page_follows_standard 必须通过；
6. 若案例有新的核查进展（官方回应/复盘确认），回填案例库并更新页面。
```

## 四、纪律红线

```text
1. 灰信号一律"观众质疑，非结论"，只作风险标注与盘口对照素材；
2. 价格路径必须真实抓取（gamma/clob 可查），禁止凭印象编数字；
3. 定性默认"高度疑似 · 待核查"，除非官方调查/选手回应等外部证据出现；
4. 不因灰信号给买卖建议；交易提醒只写"高位先减仓锁盈、不反向追单"类风控动作。
```
