# 任务 2 自动化候选流程（简化版）

最后更新：2026-08-06

一句话：系统自动"看比赛"。到什么时间、看到什么价格、比赛打到哪个阶段，就去看这场比赛值不值得做，结果放到固定位置等人确认。

任务 2 只做发现，不下单、不读私钥、不调用交易脚本。autopilot 保持关闭。

## 0. 三层框架（整个自动化的核心）

整个自动化交易就三层，一层管一件事：

```text
第一层 触发条件：什么时候去看比赛
第二层 决策规则：看到之后怎么判断值不值得做
第三层 输出与投递：判断结果写到哪里、谁去用
```

任务分工：

```text
任务 2 把三层全部跑通（发现层）
任务 4 在第三层接上交易台，人工确认后执行
任务 5 才把第二层的动作变成自动执行
```

## 1. 第一层：触发条件（什么时候去看比赛）

触发本质就是"分析比赛"，四类情况：

| 触发类型 | 条件 | 例子 |
| --- | --- | --- |
| 定时 | 每 15 分钟自动扫一遍；有比赛正在进行时加密到每 5 分钟 | 全天自动运行 |
| 赛程 | 比赛未来 2 天内开始，或最近 2 天内已开始还没结束 | 明天的 LCK |
| 价格 | 价格穿越关键阈值：跌进 10-35c、热门方跌破 40c、穿越 50% | 整场从 62c 跌到 48c |
| 阶段 | BO3/BO5 局次推进：第一局结束、进入决胜局、第三局起转整场 Moneyline | 1-1 进决胜局 |

触发前提（缺一不看）：

```text
比赛在白名单
比赛在时间窗口内
比赛还没结束
```

白名单是怎么筛的（config/market_watchlist.json）：

```text
先看游戏关键词：LoL / League of Legends、CS2 / Counter-Strike、Dota 2
再看联赛关键词：LCK、LPL、LCK Challengers、KeSPA Cup、IEM、BLAST、The International、ESL One
比赛标题同时命中"游戏关键词 + 联赛关键词"，才算白名单赛事
```

例子：`LoL: T1 vs Gen.G - LCK` 同时命中 LoL 和 LCK，进白名单；`T1 vs Gen.G` 没有联赛名，进不来。标题不含联赛名就进不了白名单，这是 live 验证时重点看 `watchlist_matches` 的原因；要加新联赛，直接往配置文件里加关键词即可。

不触发：

```text
不在白名单
已结束或接近终局
盘口太差（spread 超过 6c）
价格长时间不更新
同一场比赛 60 分钟内不重复分析（防刷屏）
```

空窗期行为（没有比赛 / 没有机会时）：

```text
没有机会 ≠ 没有比赛：比赛在进行但价格形态未触发候选，属于正常，继续按正常频率盯。
没有比赛：有白名单比赛在窗口内但尚未开赛，等临近开赛加密扫描（15 分钟内每 5 分钟）。
窗口内完全无白名单比赛：降为每小时一次保活检查，不产生空动作、不报错。
每次流水线输出下一场白名单比赛开始时间，方便人工安排。
```

## 2. 第二层：决策规则（怎么判断）

第一步：看现象——这场比赛发生了什么？

```text
P1 低价恐慌：目标方 10-35c，还有修复可能
P2 热门回撤：热门方从高位回到 40-75c，还没彻底失控
P3 中位纠缠：双方在 35-65c 反复穿越 50%
P4 强势小回撤：优势方 70-90c 的短时回撤
P5 整场反转：BO3/BO5 首局失利导致整场折价
```

第二步：定策略——这个现象用什么策略？

```text
P1 -> S1 低价反转网格
P2 -> S2 热门回撤网格
P4 -> S3 强势小回撤网格（实验阶段，只能人工复核）
P5 不单独下单，只能叠加在 S1/S2/S3 上
```

第三步：给动作——每个候选最后给一个明确结论：

```text
可生成计划      S1/S2 且盘口合格，可以准备交易计划
人工复核        实验策略或盘口一般，先看再定
仅观察          流动性不足，记下来不推荐
跳过            终局 / 盘口差 / 数据停更
```

风控闸（输出前最后检查）：每日预算 $200、单市场 $70、并发市场 3；已有持仓或未完成计划的市场不重复进队列；autopilot 关闭时一切只是建议。

## 3. 第三层：输出与投递（结果写到哪里）

### 输出什么（每次扫描）

每个候选一条记录：

```text
比赛名 + 市场
现象标签（P1-P6）
推荐策略（S1-S4）
机会分（0-100）+ 流动性分
动作（四选一）+ 理由
```

每次扫描固定产出四个文件：

```text
runtime/opportunity_candidates_live.json   候选列表（机器读）
runtime/watchlist_events.json              比赛时间线（先看日程）
runtime/candidate_action_queue.json        动作队列（只有"可生成计划/人工复核"，供交易台读）
reports/opportunity_scan_日期.md           扫描报告（人读）
```

### 发送到哪里

| 去向 | 内容 | 谁用 |
| --- | --- | --- |
| 本地 reports/ | 扫描报告 | 你直接看 |
| 本地 runtime/ | 候选列表 + 动作队列 | 执行会话 / 任务 4 交易台读取，人工点确认才执行 |
| 外部通知（可选） | 摘要：候选数、Top3 | 需要你提供邮件或 IM 通道后才启用 |

复盘回流：真实交易成交后写复盘，复盘结论再回来调触发阈值和打分权重。

## 4. 一次扫描的例子

```text
19:05 定时触发，扫到 LCK 白名单比赛正在进行。
第一局结束，某队首局失利，整场市场从 62c 跌到 48c。

现象：P5 整场反转 + P2 热门回撤
策略：S2 热门回撤网格
盘口：spread 3c，流动性分 72
机会分：79
动作：可生成计划

写入四个文件，报告里排 Top1。
你看到后决定做不做；任务 2 不会自己下单。
```

## 5. 上线顺序

```text
第一步：稳定网络下跑通 live 扫描（V2 验收 6 条）
第二步：连续 3 天定时扫描，统计候选数量和误报率
第三步：人工复核 5 个候选，确认符合直觉
第四步：接入定时调度，让触发类型从"手动"变成"定时"
第五步：动作队列接入任务 4 交易台，人工确认后走任务 1 执行链
```

## 6. 由点到面：从一个小点铺开

### 选定的小点：反弹检测（以 08-06 NIP/IG 为验收样本）

```text
要做的：单市场盯盘模式——1 分钟粒度采样 + 反弹检测。
触发规则：目标方价格 <10c 后，短时间（约 10 分钟）单根/连续拉升 >=15c，触发 P5+P1 候选。
验收方式：回放 08-06 NIP/IG 的价格路径，检测器应能复现这次触发，并输出候选 JSON、动作队列、报告三件套。
为什么选它：这场案例已入库；扫描器已有反弹指标基础；数据源支持 1 分钟粒度；触发层是目前最弱的一环（这场比赛靠人工发现）。
```

### 多种铺开方式

| 方式 | 怎么铺 | 优点 | 代价 |
| --- | --- | --- | --- |
| A 纵向切片 | 选一个触发点，把三层全串通：单市场反弹检测 -> 输出三件套 -> 人工确认 | 最早看到端到端闭环 | 一次要做的事略多 |
| B 横向切片 | 一层一层做厚：先做全触发（反弹/价格穿越/BO 阶段/定时），再做决策，再做输出 | 每一步小、单独验收 | 前几步看不到完整闭环 |
| C 数据先行 | 先把案例沉淀成标准样本 + 可回放价格数据，攒 5-10 个后再定检测阈值 | 阈值有数据支撑，不拍脑袋 | 慢，样本仍靠人工收集 |
| D 执行层先行 | 先用 NIP/IG 价格路径回测 S1 网格 + 彩票仓 + D3，验证"深反 vs 接刀"能不能被纪律兜住 | 直击最大亏损源 | 没有触发层，仍不能自动发现 |

### 推荐路线：A + C 结合

```text
第一步（点）：把 NIP/IG 的采样价格路径落成可回放样本，同时做单市场反弹检测器，用回放验收。
第二步（验证）：连续盯 3-5 场 BO3，统计检测器触发次数、候选质量、漏报/误报。
第三步（铺开，三个方向并行）：
  市场面：单市场 -> 白名单全部赛事（LCK/LPL/CS2/Dota2）-> 全电竞
  形态面：P5+P1 反弹检测 -> P5+P2 热门折价 -> 更多触发（价格穿越/BO 阶段）-> S3 实验
  深度面：只发现 -> 模拟交易 -> 小额实盘（autopilot 开启 + 彩票仓 + 交易所挂单）-> 稳定实盘
```

每一步都有复盘闭环兜底；从"点"到"面"不跳级，符合成熟度 L0-L4 原则。
