# 情报 HTML 输出 (Intel Report Generation)

项目根目录：/opt/danmu-intel。**模板为最高规范**：knowledge/INTEL_HTML_TEMPLATE.md（顶部「当前唯一标准：4 段」为最高，覆盖旧章节）。样式规范：SAP/Apple（#f5f5f7 浅底、白卡、单一强调色、系统字体栈）。

## 核心结构 (Core Structure)
**2026-10-24 用户定稿（最高，覆盖下方所有旧结构说明）：所有情报页只保留 4 段，其余栏一律不生成、禁止多写。**

**赛前页特例（2026-11-22 用户定稿，最高）：赛前节点页（S0）不再由 Codex 生成、不用下方 4 段。**
赛前页由规则层直接渲染两栏历史数据（不调用本技能）：
「1 队伍交手情况」（H2H 交战表：行=时间、列=两队、单元格=胜负，表下各自交手胜率总结）
+「2 队伍比赛近况」（两队各自近期交战表）。
数据源与实现：LoL = Riot getSchedule（结构化 winner）；CS2 = Liquipedia 队伍页
Recent Matches（锦标赛级：名次+决赛比分）；工具 tools/fetch_team_history.py（数据）
+ tools/render_pregame.py（渲染），规则层系统注入，AI 不写、不编。
Codex 只负责局中（bp/mid/end）与整场复盘页，仍用下方 4 段结构。

1. **BP 锚点与选人/地图禁选情报**（弹幕讨论·非确认）：按游戏分口径——
   LoL / Dota2 = 选人：阵容（英雄+选手）标「弹幕口径·待官方」；CS2 = 地图禁选：地图/队伍×地图强图标「弹幕口径·待官方」；
   + BP 后战绩情报（无则写「无战绩情报提及」）；禁止把弹幕讨论当实际选人（LoL/Dota2）/ 实际选图（CS2）。
2. **比赛局势**（系统注入·规则层，AI 不写本段）：两队胜率（弹幕口径·非结论）+ 虎扑队员评分。
3. **方向性情报板**：正锚点（看好谁赢，含对象/依据/时间/验证）× 负锚点（看衰谁输）× 群体共识（含分歧+样本量）× 灰信号条件预测（若兑现指向哪边）；无锚点写「今日无锚点」、无共识写「共识不足」。
4. **灰信号汇总**（风险·观众质疑非结论）：每条写明「观众质疑，非结论」+ 指向对象 + 风险等级，禁止写成实锤；无则写「今日无灰信号」。

- 每段用 `<h2><span class="no">N</span>标题</h2>` 编号（1-4 连续，禁止合并/省略/多写）。
- 整场复盘页（赛后）与局中快照页都用这 4 段骨架，数据按「当前已知」填充；缺失段保留结构、写「样本不足 / 待观察」。
- C 画像页：队伍/选手长期画像（组织/风格/核心/盘口定位），独立于上述 4 段。
- 标杆样例：reports/intel_danmu_WE-EDG_full_2026-08-19.html（仅参考样式与语言，其段数已过时，勿照抄结构）。

## 硬性门槛 (Quality Gates)
1. 数据带量（条数/提及量/密度）；2. 灰信号显著展示+纪律；3. 结果标"弹幕口径·未确认"；4. 每页至少 1 条可跨场长期沉淀；5. 无样本不硬撑、无信号不硬造。
6. **BP 后战绩情报必抓**（2026-08-21 固化）：pick 锁定后窗口内"选手×英雄"历史战绩/胜率提及（CS：图三转换窗口"队伍×地图"强图/历史战绩），无则写"无战绩情报提及"；已并入第 1 段 BP 锚点。
7. **MD 镜像必出**（2026-08-24 固化）：每个 HTML 情报页必须同步生成同名 MD 镜像到 `knowledge/intel_pages/`（规范见 knowledge/INTEL_MD_MIRROR.md），覆盖 4 段骨架全文，缺失即视为情报未交付；并在 `knowledge/intel_pages/README.md` 索引表登记。
8. **情报来源分层（2026-08-26 最高纪律）**：每条结论必须带证据来源标签（本场弹幕 / 前局弹幕 / 历史画像 / 盘口 / 推测·待验证），核心情报必须来自本场弹幕，严禁无中生有；推测显式标注「推测·待验证」并与事实分离；缺源（如 SOOP 离线）显式标注缺口，禁止用历史画像冒充本场数据。

## 语言 (Language)
HTML 内容以中文为主；技能说明中英双语。
