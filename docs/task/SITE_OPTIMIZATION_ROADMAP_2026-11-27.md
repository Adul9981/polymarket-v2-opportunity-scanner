# 弹幕情报库全站优化路线（2026-11-27）

状态：执行中
优先级：A 级
协作方式：GitHub 分支 + Pull Request；本文件是双方维护者的共同进度基线。

## 1. 当前基线

2026-11-27 实测：

| 指标 | 当前值 | 问题 |
| --- | ---: | --- |
| 形态决策台首页 | 约 25.3 MB | HTML 内嵌全部训练与历史路径，解析成本过高 |
| 形态训练原始 JSON | 约 66.9 MB | 不适合直接作为浏览器首屏数据 |

| 顶部一级入口 | 12 个 | 用户难以判断主路径 |

## 2. 目标

### 2.1 性能目标

- 首屏 HTML 小于 300 KB；
- 当前比赛首屏数据小于 100 KB；
- 历史训练数据按需加载；
- 普通 4G 网络 3 秒内可操作；
- 自动刷新无变化时可用 ETag/304，避免重复下载和重绘。

### 2.2 信息架构目标

一级导航收敛为：

```text
今日比赛
比赛情报库
形态研究
验证闭环
订阅
```

- 今日比赛：今日赛程、进行中比赛、比赛局势；
- 比赛情报库：赛前、节点、整场复盘、历史检索；
- 形态研究：决策台、图谱、画像、地图、频率和分类统计；
- 验证闭环：预测、灰信号、BP 锚点应验率；
- 订阅：套餐、登录、会员状态；
- 访问统计等运营页面移到页脚。

### 2.3 单场页面目标

同一场比赛只保留一个规范入口：

```text
match_<slug>.html
├── 当前比分 / 小局 / 阶段 / 数据更新时间
├── 首选结论：方向、价格、止盈、失效、置信度
├── 节点页签：赛前 / BP / 局中 / 结束 / 复盘
├── 情报：共识、BP 锚点、灰信号、盘口
├── 形态与价格路径
└── 数据来源、完整性、缺口
```

## 3. 分阶段执行

### P0-1：形态决策台结论与刷新体验（已完成）

- 顶部固定交易结论卡：
  - 推荐买哪边；
  - 推荐价格与当前价格；
  - 第一、第二止盈与历史触达率；
  - 失效/止损；
  - 系统判断最终更可能取胜的方向。
- 方向冲突或样本不足时明确显示“暂不推荐”“暂不判断”；
- 结构背景、样本覆盖和候选权重默认折叠；
- 主图只绘制首选延续，候选图不再堆叠历史案例和镜像线；
- 每 60 秒自动刷新、秒级倒计时、立即刷新和失败重试提示。

验收：页面回归 66 项通过；桌面和移动端视觉核验通过。

### P0-2：形态数据拆包（已完成）

- 页面 HTML 与完整训练数据分离；
- 页面壳约 119 KB（发布注入后线上实测）；
- 数据文件提供普通 JSON 和 gzip：
  - `pattern_decision_payload.json`
  - `pattern_decision_payload.json.gz`
- 支持 `DecompressionStream` 时优先读取 gzip，失败回退普通 JSON；
- 发布器同步安装 HTML、普通 JSON 和 gzip JSON。

验收：页面先解析轻量壳，再异步加载数据；gzip 文件约 3.2 MB，HTTP
`Content-Encoding: gzip` 已由 nginx 自动提供；本地浏览器实际加载、候选生成和刷新正常。

## 4. 维护协作约定

### 4.1 必须进入 GitHub 的内容

- 页面模板和生成器；
- 数据模型、接口和发布器；
- 回归测试；
- 架构与本路线文档；
- 影响展示规则的配置。

### 4.2 不进入 GitHub 的生成物

- 大型生成数据：`pattern_decision_data.json`；
- 拆分后的约 25 MB payload 与 gzip 文件；
- 静态 HTML 成品；
- runtime 缓存、日志、价格快照。

### 4.3 提交流程

```text
feature branch -> tests -> VPS deploy verification -> PR summary -> merge
```

- 分支统一使用 `codex/` 前缀；
- PR 必须写明用户可见变化、数据影响、回滚方法；
- 任何服务器手工修复必须同步回 GitHub 源码，禁止只修 VPS；
- 部署后必须验证 service、timer、页面运行时错误、数据更新时间和回滚路径。
