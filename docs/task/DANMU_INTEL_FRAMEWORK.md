# 弹幕情报库框架（Danmu Intel · 独立产品线 MVP）

最后更新：2026-08-22

## 1. 定位

观众集体智慧情报产品：把虎牙 / SOOP 直播间弹幕加工成"有预测、有闭环"的比赛情报，**单独先上线**，后续再并入大平台。

```text
不依赖大框架、不依赖行情对照、不依赖朋友历史数据——单点价值即可成立。
```

## 1.5 产品三问（最高优先级定位规则，2026-08-22）

```text
做什么：一场比赛，一页情报——实时采集虎牙 / SOOP 弹幕，加工成结构化比赛情报页
  （队伍 / 选手 / BP / 盘口 / 灰信号 / 关键时刻）。
信息价值：观众集体智慧的浓缩——谁被看好 / 被质疑、BP 评价、盘口讨论、密度峰值、
  灰信号预警；每条情报带数据与出处，可溯源。
用户获得：赛前关注点 + 盘中市场情绪与关键时刻 + 赛后预测命中 / 落空验证；
  只给情报与统计，不给买卖建议。
呈现原则：清清爽爽、定位清晰——首页一屏讲清三问；比赛情报按"一场一页"组织；
  产品整体回答"做什么 / 提供什么价值 / 用户获得什么"。
```

## 1.6 产品收敛（2026-08-23，核心优先）

```text
1. 站点只保留弹幕情报核心：首页 + 弹幕情报页（索引 / 今日比赛 / 整场复盘）+ 闭环样例 +
   灰信号统计 + 队伍 / 选手画像；平台预览页与无关功能暂时移除（需要时再恢复）。
2. 专注"弹幕情报"输出，构建观众共识层：共识 / 分歧 / 质疑全部量化、可溯源。
3. 对外文案不再带"只给情报与统计，不给买卖建议 / 不构成投资建议"字样（用户 2026-08-23 指定删除）。
4. 最简单但最有效：每场比赛一页情报 + 一个闭环验证，先跑通再逐步加功能。
```

## 2. 框架分层（2026-08-22 重新梳理）

```text
采集（多直播间实时抓取 / 断线重连 / 健康检查）
  -> 提炼（队伍 / 选手 / BP / 盘口 / 灰信号 / 密度峰值，S0-S4 阶段递进）
  -> 输出（局中监控 HTML + 整场复盘 HTML）
  -> 验证（比赛结果回填：BP 判负、灰信号、观众预测、盘口方向 -> 命中 / 落空）
  -> 沉淀（docs/data/intel 结构化库 + 画像 + 索引页 + 灰信号统计页）
```

## 3. 三大原则（框架内核）

```text
1. 可直接发布：弹幕情报页（局中 / 复盘 / 索引 / 灰信号统计）已是产品形态，静态站即可上线。
2. 发布必须带佐证闭环：每条情报页必须能从"弹幕情报 -> 比赛结果 -> 验证回填"闭环——
   有预测、有兑现 / 落空记录；没有闭环的情报不算交付。
3. 闭环是产品钩子：对外展示"观众预测命中率 / 灰信号兑现率 / BP 判负验证 / 高价值用户命中"，
   这是产品差异化的核心卖点。
```

## 4. 闭环怎么做（发布佐证）

```text
局中记录：观众预测（BP 判负 / 胜负共识 / 盘口方向）+ 灰信号（质疑对象 + 预警等级）
赛后回填：比赛结果（多信号 + 官方交叉验证，tools/verify_match_end.py）
  -> 每条预测 / 信号标注"命中 / 落空 / 待确认"
统计沉淀：预测命中率、灰信号兑现率、高价值用户命中、BP 判负验证
  -> 灰信号统计页（reports/intel_gray_signals_stats.html）+ 索引页
纪律：禁止把观众玩梗当结果（CS 误判教训）；结果待官方确认时标注"待确认"
  （验证方法论见 knowledge/VERIFICATION_METHODOLOGY.md）。
```

## 5. 发布 MVP（下一步要做出来）

```text
2. 自动发布流水线：比赛结束 -> 情报 HTML + 结构化库 -> 自动同步到站点。
```


## 7. 边界

```text
1. 只展示聚合结论与统计，不裸展示弹幕流与用户身份。
2. 灰信号 = 风险标注 + 盘口对照素材，不作假赛证据；对外写明"观众质疑，非结论"。
3. 页脚免责：仅提供情报分析，不构成投资建议。
4. 结果 / 比分必须多源交叉验证，未确认前标"待官方确认"。
```

## 8. 部署与 AI 策略（2026-08-22 评估）

```text
1. 采集位置：建议放线上（轻量 VPS，几美元 / 月）——run_danmu_session 常驻 + 自动重连；
   本地电脑只做开发 / 深度分析 / 复盘，不用常开。
2. 输出顺序（两段式）：
   即时层（线上自动）：采集 -> 规则提炼（danmu_intel）-> 基础情报页（60s 快照）-> 立即发布。
   沉淀层（本地 / 后置）：原始 JSONL + intel.json 同步回本地 -> AI 深度复盘 / 预测验证 ->
     回填结构化库 -> 终版复盘页发布。
3. AI 能力分层：
   规则管线（必配）：词表 / 计数 / 情绪粗分 / 密度 / 灰信号关键词——不依赖大模型，便宜稳定。
   LLM 解读（推荐）：BP 评价、选手状态、灰信号上下文、韩文翻译、复盘总结——
     DeepSeek 起步够用；按"接口化"设计，模型可替换（DeepSeek / GPT / Codex）。
   深度复盘 Agent（可选进阶）：比赛结束后服务器调度 LLM + 工具自动复盘；
     或保留本地 Agent 接力，结果回推线上。
4. 正式上线需要：VPS + 静态站托管（或对象存储）+ LLM API key + 数据同步（线上 -> 本地）。
   不必须：在服务器部署"我"——分析判断与闭环执行可保留本地 Agent，结果回推线上。
```
