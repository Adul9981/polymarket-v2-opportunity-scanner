# S-F1 扫描+下单工具设计（触发条件/触发状态/触发规则/执行情况）

最后更新：2026-08-15

目标：把 S-F1 完整集定价套利（Σp 错价）从"看得懂"变成"自己能跑"——
一套只读扫描 + 状态机 + 可审计执行 + 复盘闭环的工具。设计按四段框架组织：
触发条件 -> 触发状态 -> 触发规则 -> 执行情况。

本工具是"你的工具"：模块划分清晰，每步可审查、可回退、先只读后实盘。

## 0. 总体架构（一条流水线）

```text
┌──────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 扫描器    │→ │ 决策引擎      │→ │ 状态机        │→ │ 执行器        │
│ (只读)    │  │ (触发条件+规则)│  │ (触发状态)    │  │ (下单/convert)│
└──────────┘   └──────────────┘   └──────────────┘   └──────┬───────┘
     ↑                                                       ↓
┌──────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 行情/链上 │   │ 配置/白名单   │   │ 状态 JSONL   │   │ 复盘/报告     │
│ (数据源)  │   │ (config/)    │   │ (runtime/)   │   │ (reports/)   │
└──────────┘   └──────────────┘   └──────────────┘   └──────────────┘
```

设计原则：

```text
1. 扫描/决策/执行三层解耦：扫描器永远只读；执行器是唯一碰钱的入口。
2. 判定只用订单簿可成交成本，不用标记价（沿用 SCANNER_SPEC 纪律）。
3. 状态文件是防重复下单的唯一依据（沿用 runtime/ 现有约定）。
4. 先 dry-run，再小额实盘；autopilot 默认关闭，开启需用户显式授权。
5. 每笔机会留完整审计痕迹（JSONL），可回放、可复盘。
```

## 1. 触发条件（Trigger Conditions）——何时进入评估

一组机会要"有资格被评估"，必须同时满足：

| 类别 | 条件 | 默认/依据 |
| --- | --- | --- |
| 结构 | 属于负风险组（negRiskMarketID 非空） | 白名单或 gamma 结构 |
| 结构 | 组内腿数 n ≥ 5 | SCANNER_SPEC |
| 状态 | 组未结算、未过期 | gamma active/closed |
| 定价 | mark Σp 偏离：\|Σp−1\| > 2% | 一级粗筛阈值 |
| 深度 | 每腿 ask 深度 ≥ X | 二级精筛，不足则放弃 |
| 时间 | 处于可交易窗口（开赛前/赛中/结算前） | 白名单时间窗 |
| 系统 | 同组不在冷却期、风控额度未超、模式已开启 | 状态机 |

触发条件的输出：一组"候选"（candidate），进入状态机，而不是直接下单。

## 2. 触发状态（Trigger States）——机会生命周期

每个候选/每轮循环的状态机（状态持久化到 runtime/forensics/state/）：

```text
WATCH ──粗筛未命中──▶ WATCH（继续等）
   │
   └─粗筛命中─▶ CANDIDATE ──▶ VERIFYING（拉订单簿精筛）
                                   │
                                   ├─成本不达标─▶ REJECTED（记录原因，冷却）
                                   └─达标─▶ SIGNALED（等待执行）
                                                │
                                                ├─ dry-run 模式─▶ SIMULATED（模拟成交，不真下单）
                                                └─ live 模式─▶ EXECUTING
                                                                  │
                                             ┌─────────┬─────────┴─────────┐
                                             ▼         ▼                  ▼
                                          FILLED    PARTIAL            FAILED
                                             │         │                  │
                                             └────┬────┘                  │
                                                  ▼                       │
                                               CLOSED（记录本轮结果）◀──────┘
                                                  │
                                                  ▼
                                              COOLDOWN（同组冷却，防重复）
```

系统级状态（整个工具）：

```text
DISABLED（默认，不评估）-> SCANNING -> THROTTLED（频率受限）
-> PAUSED（异常自动暂停：连续失败/超风控/数据不更新）-> RESUME（人工）
```

状态文件字段（json，供防重与复盘）：

```json
{
  "group": "nba-2027-champion",
  "cycle_id": "2026-08-15T12:00:00Z-nba-2027",
  "state": "SIGNALED",
  "side": "NO",
  "n_legs": 30,
  "mark_sump": 1.048,
  "ask_cost": 28.7,
  "verdict": "pass",
  "ts_start": 1786900000,
  "ts_end": null,
  "tx_hashes": []
}
```

## 3. 触发规则（Trigger Rules）——如何判"可以出手"

### 3.1 一级粗筛（标记价，15–30 分钟一次）

```text
命中：|mark Σp − 1| > 0.02（默认 2%）
未命中：不消耗订单簿请求
```

### 3.2 二级精筛（命中后立即，订单簿 ask）

```text
对组内每腿：按 ask 逐档加权，凑够目标数量 X：
  cost_i = Σ(档位价 × 该档数量)，直到累计 ≥ X
  depth_i < X 则该腿按可买数量打折；深度严重不足整组放弃
```

### 3.3 出手判定（两侧公式，摩擦+安全垫）

```text
NO 侧（Σp > 1）：
  total_cost(NO) < (n−1) × X × (1 − 摩擦) − 安全垫
  n=10, X=1：cost < $9 × 0.98 − 0.01 = $8.81

YES 侧（Σp < 1）：
  total_cost(YES) < X × (1 − 摩擦) − 安全垫

摩擦：1%~2%（手续费/燃气/滑点）；安全垫：0.5%~1%（回测后校准）
```

### 3.4 执行规则

```text
1. 只读/模拟（L1-L2）：扫描+判定+模拟成交，不创建订单。
2. 实盘（L3+）：先 dry-run 生成计划 -> 用户确认 -> autopilot 开启才执行。
3. 固定金额制：单轮/单市场/每日限额写死在 config，超限即停。
4. 订单只从执行器发出；扫描器和决策引擎永远不下单。
5. Convert/Merge 链上动作：见"能力缺口"一节，补齐前不进入实盘。
```

## 4. 执行情况（Execution Status）——怎么知道做没做、赚没赚

### 4.1 每轮审计记录（JSONL，每行一轮）

```json
{"ts": 1786900000, "group": "nba-2027", "n_legs": 30, "side": "NO",
 "mark_sump": 1.048, "ask_cost": 28.70, "notional": 29.00,
 "net_est": 0.30, "state": "FILLED", "tx_hashes": ["0x..."],
 "fees_usd": 0.05, "notes": ""}
```

### 4.2 订单/资金状态跟踪

```text
订单：PLACED -> PARTIAL -> FILLED / EXPIRED / CANCELLED / FAILED
资金：买入成本 -> Convert 现金 (n−1)X -> Merge 回笼 -> 净利 = 现金+剩余份额 − 成本
链上确认：交易 hash + 结算状态（RPC/区块浏览器复核）
```

### 4.3 每日报告（reports/）

```text
1. 触发次数/命中率：粗筛命中 vs 精筛通过 vs 实际执行
2. 错价频率：每组每天 Σp 偏离的持续时长分布
3. 可成交性：ask 成本 vs 标记价差（滑点）、深度不足比例
4. 盈亏：单轮毛利分布、扣摩擦净期望、累计曲线
5. 异常清单：连续失败、超时、风控暂停记录
```

### 4.4 告警与暂停（自动）

```text
连续 3 轮 FAILED / 数据长时间不更新 / 接近结算 / 风控超限
-> 自动 PAUSED，人工确认后 RESUME
```

## 5. 分步实施路线（对应成熟度 L0→L4）

| 步骤 | 内容 | 产物 | 门槛 |
| --- | --- | --- | --- |
| Step 0 | 本设计定稿 + 配置/白名单/阈值 | docs + config/forensics_arb.json | 用户确认 |
| Step 1 | 只读扫描器 v0（两级） | tools/forensics_arb_scanner.py + 每日报告 | 跑满 2 周统计窗口 |
| Step 2 | 回测模块 | tools/forensics_arb_backtester.py | 净期望为正才继续 |
| Step 3 | 状态机+候选队列+模拟执行 | tools/forensics_arb_engine.py（dry-run） | 模拟 1 周无异常 |
| Step 4 | 小额实盘试点 | 执行器 + polydata 能力补齐 | 用户授权 + 风控放行 |
| Step 5 | 稳定运行 | 调度/告警/复盘闭环 | 连续 N 天盈利 |

每步之间是硬门槛：Step 1 数据不达标不回测；回测不为正不模拟；模拟不干净不实盘。

## 6. 落地文件规划

```text
config/forensics_arb.json           白名单组、阈值、限额、模式开关
schemas/arb_cycle.schema.json       状态/记录字段契约
tools/forensics_arb_scanner.py      Step 1：两级只读扫描，输出 JSONL + 报告
tools/forensics_arb_backtester.py   Step 2：价格历史重放 + 模拟 Convert/Merge
tools/forensics_arb_engine.py       Step 3：状态机 + 候选队列 + dry-run 执行
runtime/forensics/state/            每组每轮状态 JSON（防重依据）
runtime/forensics/scan_YYYY-MM-DD.jsonl  扫描/执行审计日志
reports/forensics_arb_*.md          每日/每周统计报告
```

## 7. 能力缺口（实盘前必须补齐，需用户决策）

```text
1. Convert/Merge 链上操作：polydata 钱包项目目前只有买卖网格接口，
   没有转换/合并能力。补齐两条路任选：
   a) 扩展 polydata（需要用户显式授权改它的代码）；
   b) 用 Polymarket 官方/前端同款合约调用（NegRiskAdapter 0xada2... +
       CTF 0x4d97...），自己实现签名与广播（不碰私钥原则下要单独设计）。
2. 返佣确认（S-F2）：平台返佣规则未在文档确认，影响净利估算。
3. 订单簿历史：回测只能用标记价 + 滑点假设近似 ask，精度有限。
4. 实盘风控：单轮/单市场/每日限额与并发上限，写进 config 由风控放行。
```

## 8. 边界与纪律（红线，全部阶段生效）

```text
1. 扫描与决策永远只读；只有执行器碰钱。
2. 判定只用订单簿可成交成本；标记价只做粗筛。
3. 不读/不移动私钥；polydata 仓库只调用接口，改动需显式授权。
4. 未到 L2 回测为正之前，不进入任何实盘路径。
5. 自动暂停规则优先于一切；异常状态不硬闯。
6. 本工具只做规则套利（市场侧价差），不做攻击性交易；代码缺陷走赏金上报。
```
