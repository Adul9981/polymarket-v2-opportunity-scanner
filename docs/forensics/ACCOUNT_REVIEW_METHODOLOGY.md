# 账户级复盘方法论（Account Review Methodology）

最后更新：2026-08-20

目标：把"某个外部账户为什么赚 / 为什么亏"拆成**可验证的统计结论** +
**可复制 / 可避免的规则**，而不是一句"他很强 / 他爆仓了"。
本方法是任务 7（交易者拆解）的账户级复盘标准流程，与 DISSECTION_GUIDE.md
（逐场拆解）互补：逐场拆"一笔交易怎么做的"，账户级复盘拆"一个账户的钱
从哪来、怎么赚的、能不能复制"。

## 必答三问

```text
Q1 钱从哪些市场来？   -> 赛项 / 价带 / 市场类型 / 退出方式 / 盈利集中度
Q2 他用了什么策略？   -> 策略模式定义 + 量化画像（样本 / 胜率 / ROI / 代表事件）
Q3 这些策略可不可复制？ -> 复制前提 / 项目映射 / 成熟度建议 / 风险与反面纪律
```

三问全部回答完，复盘才算完成；只回答 Q1 的是流水账，只回答 Q2 的是猜测。

## 五步流程

### 1. 取数与校验

```text
按根 AGENTS.md 防错规则第 10 条（链接处理 SOP）执行：
用户名 -> 地址（公开索引/快讯交叉验证）-> data-api /trades /activity /positions
全量分片拉取（takerOnly=false、按日分窗、重试退避），原始 JSON 落盘
docs/forensics/data/<目标>/（只增不改），并与社区快讯/转载交叉验证。
```

### 2. 盈亏曲线与阶段划分

```text
口径统一：买入/卖出按 activity usdcSize（含费），赎回按 size × $1；
另记无费口径（size × price）对照。输出：峰值/谷底/期末/最大回撤/
单日极值/累计为正天数/最长连续为正天数 -> 据此划分阶段（起步/盈利期/崩盘期）。
```

### 3. 市场结构拆解（回答 Q1）

```text
必出四张表 + 一个集中度：
a. 买入价带 × 净盈亏（<0.2 / 0.2-0.4 / 0.4-0.6 / 0.6-0.8 / ≥0.8，按事件加权均价）
b. 赛项 × 价带 交叉表（判断力是否赛项特异）
c. 市场类型（单局/系列赛/晋级/冠军/让分/BO1）盈亏
d. 退出行为（持仓时长中位、归零仓位数、赢定后离场占比）
e. 盈利集中度（TOP10/20/30 占盈利比例）-> 判断是"少数重仓驱动"还是"稳定复利"
```

### 4. 策略模式识别与量化（回答 Q2）

```text
按价带/赛项/市场类型聚类出 3-5 个可命名模式，每个模式给：
定义（触发条件、仓位、退出方式）、样本数/胜率、累计买入、净盈亏、ROI、
代表事件、判定（盈利引擎/中性/失血带/失败模式）。
所有结论分级：接口数据（硬）vs 行为推断（软），推断必须标注"推断"。
```

### 5. 可复制性评估（回答 Q3）

```text
对每个模式回答：
a. 统计是否支持复制（样本量、ROI、胜率、赛项边界）；
b. 复制前提是什么（判断力/数据/资金/工具）；
c. 映射到项目策略库哪个条目（S1-S4 / S-Fx），建议成熟度（L0-L4）；
d. 必须避开的反面纪律（无止损/赛项漂移/追损/仓位失控）登记为红线样例。
```

## 输出规范与回流

```text
1. 拆解卡：docs/forensics/cases/YYYY-MM-DD_<slug>/README.md（必答三问模板见下）
2. 可视化报告：reports/trader_analysis_YYYY-MM-DD_<slug>.html（SAP/Apple 风格）
3. 原始数据：docs/forensics/data/<目标>/（只增不改）
4. 回流（必须）：
   KNOWLEDGE_BASE.md   账号档案 + 策略统计 + 新规则
   STRATEGY_LIBRARY.md 新模式登记（L0 观察起步）或样本/成熟度更新
   cases/README.md     跟踪表
   PROJECT_PROGRESS.md 任务 7 状态
```

## 拆解卡"必答三问"模板

```markdown
## 基本信息（账号/地址/活跃期/成交/盈亏关键数字）
## 一句话结论
## 数据与方法（来源/口径/文件）
## 时间线（阶段划分 + 逐日关键）
## 深拆一：钱从哪些市场来（Q1 四张表 + 集中度）
## 深拆二：策略模式识别（Q2 模式表）
## 深拆三：可复制性评估（Q3 复制判定 + 项目映射 + 反面纪律）
## 新闻 × 数据交叉验证
## 行为特征 / 模式标签
## 风险与失败模式
## 结论与下一步验证
```
