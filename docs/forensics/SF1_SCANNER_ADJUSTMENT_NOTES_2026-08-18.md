# 结构套利（S-F1 完整集）扫描器调整清单

日期：2026-08-18
用途：给扫描器维护者的调整清单与实测依据。只读工具、不下单；红线同项目：不碰私钥、不攻击合约。

## 一、必须调整的关键项（按优先级）

### 1. 真实成交腿过滤（当前最大噪音源）

```text
- 只统计 lastTradePrice 与 bestBid 双非空的腿；gamma 列表的 funded 字段不可靠
  （NFL 冠军盘 $34 万流动性仍返回 funded=false）。
- 死盘/默认价 0.5 的腿会制造 Σp 假象：日报里 Σp=2.9 的组还在精筛，
  粗筛命中率 71% 大部分是死盘噪音。必须加 sanity：0.7 ≤ Σp ≤ 1.3，
  超出标记 artifact 且不进精筛。
- 已结束未结算的僵尸盘（endDate 已过仍 closed=false）直接排除。
```

### 2. 组内按 negRiskMarketID 去重

```text
- 同一事件可能含多个负风险组，混算会出现 Σp=26.5（NBA 新秀 81 腿）、
  7.55（欧冠 42 腿）这类聚合假象；必须分组求和，白名单去重。
```

### 3. 订单簿口径（ask Σp 不是 best-ask 求和）

```text
- 退化盘口（0.99 卖墙）会让 best-ask 求和得出 17.456 / 31.138 这类垃圾值，
  不能当可成交口径。
- 判定一律用逐档加权可成交成本（walk asks 凑够 X）。
- 任一腿盘口为空/404/深度不足 => 该腿不可用；整套不可成交时判 infeasible，
  不要报"毛利 = −成本"这种无意义值。
```

### 4. 换成真实费用模型（废弃 2% 固定摩擦）

```text
- Polymarket 官方公式：fee = C × feeRate × p × (1−p)
- 费率：天气/体育 0.05、政治/金融/科技 0.04、地缘 0
- gas 按 $0.05/轮；taker 返佣按官方 tier（保守先设 0）
- 真实费用约为 NO 名义金额的 0.5%~0.6%；2%+1% 安全垫会把 0.7%~1.5%
  的真实窗口全部挡掉。
```

### 5. Convert 费率与公式（链上确认）

```text
- Convert 兑付：交 k 条 NO（每腿 X）-> 现金 (k−1)×X×(1−feeBps/10000)
  + 补集 YES×(1−feeBps/10000)。feeBps 按市场配置，2026-08-15 实测
  NFL/NBA/MLB/EPL/UCL 全部 = 0，但机制存在，扫描器要参数化。
- n≤1 不可 Convert；单腿（k=1）无现金，只给补集 YES。
```

### 6. 扫描池与粒度（e46m3 型窗口是分钟级）

```text
- 10 分钟轮询太粗；他单轮约 30 秒，窗口持续数分钟。
- 只扫"48h 内结算 + 成交量前 3000 + weather 分类"会漏掉盘中比分盘
  （主战场）与当日天气盘。
- 建议：白名单小池 1–5 分钟精扫 + 命中即精筛；粗筛 15–30 分钟。
```

### 7. X 大小要报"边随份额衰减"

```text
- 固定 X=12.8 会走进坏价格，错过只在盘口前几档存在的边。
- 同时评估 X=1/2/5/10/25/50，输出哪一档净利转负（参考我们 8/15 马德里：
  X=1 毛边 +0.37%，X=50 转负）。
```

### 8. Σp<1 方向必须做穷尽性/久期检查

```text
- YES 完整集只有在腿集合穷尽（含 field/其他腿）时才成立；政治提名盘
  Σp=0.93 多为未列候选的残差概率，不是套利。
- 结算 >90 天的 YES 侧通过项标 pass_long_dated（久期价值，非即时套利）。
```

### 9. 网络与空结果自检

```text
- Python urllib 默认 SSL 校验会被本机自签名证书拦截（curl 正常），
  扫描器需证书降级容错，否则会静默漏抓（我们已踩过并修复）。
- 空结果必须自检：抓取为 0、精筛 0 pass 都要先交叉验证再下结论，
  禁止直接报"无机会"（项目防错最高优先级规则）。
```

### 10. 回测口径（先修这个再谈结论）

```text
- 现有回测用合成成交价：(1−标记价)×(1+滑点)，不是真实 ask 历史，
  结论失真（吉达 8/12 窗口 31 个时点全部净利为负就是该模型的结果）。
- 改为真实 book 历史重放：逐腿走 ask 阶梯、按 X 凑量、扣官方费用+gas，
  才能判断 S-F1 在吃单模式下是否为正。
```

## 二、实测结论（为什么"几天 0 机会"需要拆成两层看）

```text
1. 吃单口径下"无机会"成立（三天交叉验证一致）：
   - 我们 8/15 精筛 15 组（NFL/NBA/MLB 冠军、3 个当日天气、MLB 榜、
     MLS 金靴、共和党提名等）全部 fail/infeasible；
   - 朋友 8/16~8/18 精筛 908 条 pass=0；
   - 我们 8/18 对日报同批组重扫：比分盘 NO 成本 14.69 vs 理论 14
     （毛边 −4.71%）、西雅图降水组为死盘、釜山天气盘腿无盘口、NFL 榜 0 深度。
2. 原因不是"市场没机会"，而是订单簿把 NO 侧报得几乎精确等于兑付值，
   标记 Σp 的偏差（5%~7%）在盘口里只剩 0.03%~0.4%，扣真实费用后为负。
3. e46m3 的利润大概率来自做市挂单+返佣+极小单高频（单笔中位 $0.70），
   吃单价差路径目前未被任何回测/扫描复现为正。
```

## 二.5 机会到底存不存在、多久一次（8/18 链上成交对账）

用 e46m3 吉达窗口的真实数据回答"是不是很难发生"：

```text
1. 标记口径：机会很多。吉达窗口 79 小时标记价序列：
   Σp≥1.02 占 73.7%、≥1.03 占 59.1%、≥1.04 占 40.6%、≥1.05 占 17.4%；
   Σp≥1.03 的最长连续段 796 分钟（13 小时+）。均值 1.0325。
2. 他的成交口径：21 笔 NO 买入价 vs 同刻公平价(1−标记) 的折扣几乎为零
   （181 美元成本上总折扣仅 +$0.02）——他是按公平价买入，不是买"便宜货"。
   利润 = (Σp−1)×X 来自"整套 YES 被市场标到 1.03~1.07"，Convert 公式兑现。
3. 所以机会的真实形态是：订单簿 NO 价格跟踪标记价（NO≈1−YES_mark）且
   Σp>1 的窗口。吉达窗口大部分时间处于该状态。
4. 我们 8/15、8/18 采样失败的原因是：采样时刻订单簿已收敛
   （NO 成本≈n−1，盘口隐含 Σp≈1），标记价却滞后显示 1.03~1.07——
   那是"标记错、盘口对"的状态，确实无机会。
5. 8/17 回测显示全负，是因为用了合成成交价 (1−标记)×(1+滑点) 且按
   X=10 全时点模拟，不是真实盘口证据；真实盘口证据（他的成交）是正的。
结论：机会存在且按标记口径频繁出现；"盘口口径"的频率尚未被测量，
必须用真实 ask 历史采样（结算前天气盘 + 赛中比分盘，1-5 分钟粒度）
统计"NO 全套成本 < n−1−费用"的窗口占比，才能给出准确频率。
```
