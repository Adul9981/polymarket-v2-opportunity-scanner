# 预测市场网格交易工具产品说明

## 1. 产品定位

这是一个面向 Polymarket 等预测市场的网格交易辅助系统。电竞、体育只是最典型的使用场景，因为这类市场在比赛过程中会频繁出现赔率拉扯、快速反转和终局跳变。

系统不以“预测谁最终获胜”为核心，而是识别预测市场中常见的价格拉扯行情：

- 弱势方快速缩距
- 双方价格接近 50%
- 价格多次穿越 50%
- 短时间内大幅波动
- 盘口和成交量足够支持交易

系统发现机会后，生成标准交易配置，并交给现有执行脚本完成挂单、成交后立即挂卖单、分批止盈和彩票仓保留。

## 2. 网格交易的第一性原理

预测市场价格本质上是一个 0-1 区间内的概率价格。比如 25c 可以理解为市场认为该结果约有 25% 概率发生，100c 代表结果命中，0c 代表结果失败。

网格交易在预测市场里的基础逻辑是：

```text
1. 价格有边界：最低接近 0c，最高接近 100c。
2. 不确定阶段会反复波动：比赛、体育、选举、新闻事件都会在信息更新中来回定价。
3. 高波动阶段不一定需要判断最终结果，只需要捕捉价格回摆。
4. 低价买入后，成交即挂卖，可以把退出动作前置，降低人工反应滞后。
5. 分批卖出可以先回收本金和利润，剩余小仓位变成彩票仓。
```

这个工具要赚的不是“猜中最终赢家”的钱，而是：

```text
低位成交
-> 反弹卖出
-> 重复多轮
-> 少量仓位搏最终 100c
```

### 2.1 为什么预测市场适合做网格

预测市场和普通资产不同，它有几个天然特征：

```text
价格有上限和下限：
- 价格只在 0c-100c 之间波动。

信息驱动明显：
- 比赛比分、回合、事件进展会不断改变市场预期。

中间区间波动高：
- 25c-75c 之间最容易出现反复拉扯。

终局阶段跳变大：
- 一旦结果接近确定，价格会快速冲向 100c 或 0c。
```

因此，网格策略的核心不是无限加仓，而是只参与“仍有不确定性、流动性足够、价格有来回空间”的阶段。

### 2.2 网格是否成立的核心公式

一轮交易必须满足：

```text
预期反弹收益 > spread + 滑点 + 未成交风险 + 终局跳变风险
```

换成产品语言：

```text
如果价格虽然波动，但盘口薄、spread 大、已经接近终局，就不应该交易。
如果价格在 25c-75c 之间反复波动，成交量高，spread 小，才值得开网格。
```

### 2.3 策略边界

网格交易最怕三件事：

```text
1. 单边趋势：
   买入后不反弹，直接归零。

2. 终局跳变：
   比赛突然接近结束，价格快速从 30c 跌到 1c。

3. 低流动性：
   图表看起来波动，但真实盘口无法成交或卖出。
```

所以系统必须先识别：

```text
是否还有波动空间
是否有足够流动性
是否已经进入终局风险
```

## 3. 产品结构

产品分为两层。

```text
第一层：机会发现层
- 找比赛
- 早期识别波动机会
- 计算早期预警分和纠缠指数
- 生成交易信号

第二层：执行管理层
- 固定单场预算
- 分层买入
- 买单成交后立即挂卖单
- 分批回收本金和利润
- 保留彩票仓
- 控制轮数和风险
```

现有执行脚本已经具备“设置金额 -> 自动挂买单 -> 成交后自动挂卖单”的能力，因此第一版重点是补齐机会发现层和交易配置生成器。

## 4. 产品路径

```text
市场扫描
-> 候选池筛选
-> 实时价格监听
-> 早期预警
-> 纠缠指数确认
-> 生成交易配置
-> 人工确认或自动触发
-> 调用执行脚本
-> 成交后立即挂卖单
-> 分批回收
-> 保留彩票仓
-> 日志复盘
```

第一版建议保留人工确认，系统负责把机会和配置推到用户面前。

## 5. 机会发现层

### 5.1 候选池筛选

赛前筛选不要过窄，赔率不需要必须在 35c-65c。第一版建议：

```text
进入候选池：
- 高波动事件市场优先
- 体育/电竞的单局、单节、单场 Winner 市场优先
- BO3 / BO5、第四节、决胜盘、关键局等不确定性强的场景优先
- 任一方价格 >= 25c
- 成交量较高
- spread 可接受
- 热门赛事、热门队伍、热门对局优先

排除：
- 低成交量
- spread 过大
- 盘口深度不足
- 一方低于 8c 且没有强流动性
- 价格已经 92c 以上且不是已有仓位
```

### 5.2 热门程度评分

热门程度不是只看赛事名称，要结合市场数据。

```text
赛事维度：
- 顶级赛事、国际赛、季后赛、淘汰赛优先
- 知名队伍优先
- BO3 / BO5 优先

市场维度：
- 成交量
- 盘口深度
- spread
- 价格更新频率
- 最近成交连续性
```

## 6. 早期预警分

早期预警分用于尽快进入交易准备状态，避免等图表已经长时间纠缠后才识别。

核心目标：

```text
第一次明显缩距或第一次穿越 50% 时，就应该进入 READY。
```

建议指标：

```text
弱势方快速上涨：
- 弱势方上涨 10c：加分
- 弱势方上涨 15c：明显加分
- 弱势方上涨 20c 以上：强信号

靠近 50%：
- 从 25c-35c 快速进入 40c-55c，进入准备状态

第一次穿越 50%：
- 进入 READY

成交活跃：
- 最近成交连续
- order book 更新频繁

spread 可接受：
- spread 小于 5c 优先
- spread 大于 8c 谨慎或跳过
```

信号等级：

```text
WATCH：继续监控
READY：进入交易准备状态，允许生成候选配置
TRADE：允许调用执行脚本
SKIP：不交易
STOP_NEW：停止新开仓
```

## 7. 纠缠指数

纠缠指数用于确认是否已经进入高波动、可交易的拉扯状态。

建议分数为 0-100。

### 6.1 指标优先级

```text
1. 多次穿越 50%
2. 弱势方快速缩距
3. 短期累计波动大
4. 价格停留在 25%-75%
5. 明显反转次数
6. 流动性质量
```

### 6.2 50% 穿越

这是最重要的指标。

```text
0 次穿越：只观察
1 次穿越：READY
2 次穿越：强 READY / 轻 TRADE
3 次以上：TRADE 优先级高
```

### 6.3 短期累计波动

计算 5-15 分钟内的绝对价格变化总和。

```text
例：
30 -> 48 -> 39 -> 55 -> 43
累计波动 = 18 + 9 + 16 + 12 = 55c
```

建议：

```text
25c 以下：弱
25c-50c：可观察
50c-80c：较强
80c 以上：强
```

### 6.4 中位区间

```text
理想区间：30c-70c
可接受区间：25c-75c
谨慎区间：20c-80c
危险区间：低于 8c 或高于 92c
```

### 6.5 流动性

图表形态必须被流动性确认。

```text
关键指标：
- bid/ask spread
- 目标价格附近深度
- 最近成交连续性
- order book 更新频率
```

如果流动性不达标，即使纠缠指数高，也不执行。

## 8. 市场赔率形态库

市场赔率变化看多后，通常可以归纳成几类固定形态。系统不应只看单个指标，而应先做形态识别，再结合纠缠指数决定动作。

### 7.1 形态 A：早期缩距

```text
特征：
- 赛前或开局一方 25c-35c
- 短时间快速上涨到 40c-55c
- 强势方优势明显收窄

动作：
- 进入 READY
- 允许生成交易配置
- 不一定马上成交，优先挂低价等待单
```

### 7.2 形态 B：50% 反复穿越

```text
特征：
- 价格多次穿越 50%
- 双方反复互换优势
- 短期累计波动大
- 盘口仍然有流动性

动作：
- 进入 TRADE
- 启动低价分层买入
- 成交后立即挂卖单
- 允许做 1-2 轮波动交易
```

### 7.3 形态 C：长时间中位震荡后突破

```text
特征：
- 长时间在 35c-65c 或 25c-75c 之间震荡
- 中后段突然向 75c/25c 或更极端区间突破
- 常见于 CS 第三图、LOL 关键局、篮球第四节、网球决胜盘等

动作：
- 早期和中段可以交易
- 突破到 80c 以上后减少新开
- 突破到 92c 以上后停止新开，只管理已有仓位
```

### 7.4 形态 D：终局封顶/归零

```text
特征：
- 一方快速冲到 95c-100c
- 另一方跌到 5c 以下
- 曲线变成接近水平线

动作：
- 禁止新开仓
- 只处理已有卖单或彩票仓
- 不因为价格便宜继续加仓
```

### 7.5 形态 E：低流动性假波动

```text
特征：
- 图表看起来跳动很大
- spread 很宽
- order book 很薄
- 最近成交不连续

动作：
- SKIP
- 只记录，不执行
```

### 7.6 形态识别输出

每个市场实时输出：

```json
{
  "pattern": "MID_CHOP_BREAKOUT",
  "signal": "READY",
  "confidence": 0.82,
  "reason": ["price_inside_25_75", "crossed_50_once", "volume_ok"],
  "blocked_by": []
}
```

形态识别与信号关系：

```text
早期缩距：WATCH -> READY
50% 反复穿越：READY -> TRADE
中位震荡后突破：TRADE -> STOP_NEW
终局封顶/归零：STOP_NEW
低流动性假波动：SKIP
```

## 9. 不依赖实时比分的处理

第一版优先依赖预测市场自身数据：

```text
- 当前价格
- bid / ask
- spread
- order book 深度
- recent trades
- 成交量
- 价格路径
- 更新时间
```

不强依赖：

```text
- CS 当前回合
- LOL 大龙/小龙/远古龙
- 篮球每回合细节
- 其他比赛事件级数据
- 是否赛点
- 具体比分
```

没有比赛内数据时，用赔率代理风险：

```text
价格突然 >92c：停止新开仓
价格长时间 >95c：只管理已有仓位
spread 突然扩大：停止新开仓
盘口深度消失：停止新开仓
数据长时间不更新：暂停交易
```

后续版本可以接入比分数据作为增强风控。

## 10. 执行管理层

执行层使用固定金额，不按总资产比例做第一版。

核心参数：

```text
match_budget：单场预算
cycle_budget：每轮预算
max_cycles：最大交易轮数
buy_ladders：买入阶梯
sell_plan：成交后的卖出计划
lottery_cost_basis_usd：彩票仓固定成本金额
stop_new_entry_below：停止新开低价阈值
stop_new_entry_above：停止新开高价阈值
```

示例：

```json
{
  "match_budget": 100,
  "cycle_budget": 25,
  "max_cycles": 2,
  "buy_ladders": [
    { "price": 0.30, "amount": 10 },
    { "price": 0.25, "amount": 10 },
    { "price": 0.20, "amount": 5 }
  ],
  "sell_plan": [
    { "price": 0.40, "sell_cost_basis_usd": 7.5 },
    { "price": 0.50, "sell_cost_basis_usd": 7.5 },
    { "price": 0.60, "sell_cost_basis_usd": 6.25 }
  ],
  "lottery_cost_basis_usd": 3.75,
  "stop_new_entry_below": 0.08,
  "stop_new_entry_above": 0.92
}
```

## 11. 多轮交易逻辑

这不是一笔交易结束，而是多轮低买高卖。

每一轮：

```text
低价买入
成交后立即挂卖单
反弹后分批卖出
保留彩票仓
等待下一次回落
```

第一版建议：

```text
每场最多 2 轮
每轮最多 3 层买入
每轮最多 3 档卖出
彩票仓 10%
不做无限网格
```

## 12. 成交后立即挂卖

这是执行层核心要求。

```text
买单成交后，不等待人工判断。
系统立即按照 sell_plan 挂出卖单。第一版采用固定金额制，不使用账户比例或动态百分比加仓。
```

示例：

```text
买入均价 25c
卖出 1：33c，卖 30%
卖出 2：40c，卖 40%
卖出 3：50c，卖 20%
剩余 10% 留彩票仓
```

## 13. 彩票仓

彩票仓只来自已经反弹后的剩余仓位。

```text
彩票仓金额：固定成本金额
默认：每轮预算中预留一小笔固定金额
本金未回收前，不扩大彩票仓
彩票仓不继续加仓
价格进入极端区间后，只管理已有彩票仓
```

彩票仓目标：

```text
20c 买入
40c 卖出大部分
剩余小仓最终可能涨到 100c
```

## 14. 强制停止规则

```text
价格 > 92c 或 < 8c：停止新开仓
spread > 8c：停止新开仓
盘口深度不足：停止新开仓
数据长时间不更新：暂停
单场轮数达到上限：停止新开仓
单场预算用完：停止新开仓
```

## 17. 产品原则

```text
从 0-1 有界价格出发
只做有波动空间的市场
早发现，不晚追
先判形态，再算分数
用赔率，不强依赖比分
固定预算，不无限加仓
低价买，不追高
成交后，立刻挂卖
先回收，再彩票
盘口薄，不交易
价格极端，不新开
有日志，能复盘
```
